# USER.md — 함께 일하는 사람

> 🔴 **세션 중 수정하지 않는다.** 바꾸려면 사람이 명시로 지시한다. 새 프로젝트(`new-project`)에서는 그 프로젝트의 사람으로 바꾼다.
> ⚠️ project-start-guide-05 에서는 사용자를 "Nova"라고 불렀다. **이 저장소에서 Nova 는 플랫폼 이름**이므로 사용자는 "사용자"로 부른다(헷갈림 방지 — Claude 판단, [ADR-007](../../docs/adr/ADR-007-soul-layer.md)).

## 누구인가
- 한종열(Julian Han) — 누리인프라(NURIINFRA) 기획이사
- AI 서버 · SI/NI · 보안관제(MSSP)에 특화된 IT 인프라 회사
- 이 저장소에서의 역할: **기획 · 설계자**(CLAUDE.md "사용자는 기획 · 설계자")

## 하는 일
- 여러 플랫폼 프로젝트(5~7개)를 함께 기획 · 설계 총괄한다
- Nova 는 그 프로젝트들의 **공통 출발점**이다 — 여기서 만든 규칙 · 코드가 모든 새 프로젝트로 간다

## 일의 조건
- **병렬 개발이 기본** — 프로젝트 여럿이 동시에 돈다
- **속도가 매출로 이어진다** — 하루 지연이 프로젝트 수만큼 곱해진다
- **기회비용에 민감하다** — 결정마다 검증의 비용을 밝혀 준다

## 설명 없이 통하는 분야
- 인프라: k3s · MSA · vLLM · GPU 서버
- 플랫폼: 멀티테넌트 SaaS · AX(AI 전환) · git worktree 병렬 개발
- 한국 규제: ISMS-P · 개인정보보호법 · AI 기본법

## 일하는 방식
- **명세 먼저(속도에 맞춰)** — 코드 전에 요구 · 계획을 세우되 완성도는 되돌림 가능성에 비례한다
- **문서화 · 형상관리 중심** — 모든 결정과 작업이 기록으로 남아야 한다
- **설계 우선 · 병렬 운영**
- 되돌릴 수 있으면 과감하게, 되돌리기 어려우면 신중하게

## 협업에서 바라는 것
- **모든 대화와 기록은 한국어** — 여러 번 강조했다(CLAUDE.md 규칙 0)
- 결론을 먼저, 근거는 뒤에
- 대가(trade-off)를 분명히 — 속도와 정확도 사이의 것도
- 놓친 관점을 짚어 주기
- 확신 없는 것은 확신하지 않기
- 판단을 대신하지 말고 **판단 재료**를 주기
- 직접 써 보고 확인할 수 있게(실제 화면 · 미리보기 · 근거 링크)
