# /deep-audit — 다축 병렬 심층 감사

저장소를 **여러 전문 시각에서 동시에** 파헤쳐 개선점을 찾고 **처분까지** 간다. 발견만 늘어놓고 끝내는 보고는 절반이다.
참조: project-start-guide-05 `/deep-audit` 를 Nova 의 게이트 · 기록 위치 · Superpowers 스킬에 맞게 다시 썼다.

인자: `$ARGUMENTS` (비면 전체)

## 0. 지키는 다섯 가지
1. **이미 게이트가 보는 것은 분모에서 뺀다** — `python nova.py lint` · `test` 가 잡는 것을 다시 보고하면 소음이 되고, 진짜 발견이 묻힌다. 축은 게이트 **밖**을 겨눈다(§1 표)
2. **분모를 말한다** — 축마다 무엇을 몇 개 봤는지 적는다. 0건 통과는 통과가 아니다. 못 본 것은 "없다"가 아니라 "안 봤다"로 적는다
3. **발견은 결론이 아니라 가설이다** — 병렬 에이전트 보고에는 중복 · 상충 · 과장이 섞인다. 통합 · 반증(§4)을 거치기 전에는 고치지도 기록하지도 않는다
4. **되돌릴 수 있는지로 고칠 것과 제안할 것을 가른다** — 파일 편집 · 검사 보강은 고친다. API 계약 · DB 구조 · 삭제 · 외부 노출 · 의존성 추가 · 권한 확대는 **제안까지만** 하고 사용자가 정한다
5. **판단 문장은 맡기지 않는다** — "왜 그렇게 판단했나 · 무엇이 반증됐나"는 메인이 쓴다. 축 에이전트는 재료만 낸다
- 모든 위임 · 보고 · 기록은 **한국어**다(CLAUDE.md 규칙 0). 축 에이전트에게도 "한국어로 보고"를 지시한다

## 1. 범위와 분모를 먼저 고정한다
```
git status -s
uv run python scripts/audit_scope.py [범위 경로 …]        # 분모 표 — 축별 대상 수 · 제외(생성물 · 잠금 · 캡처)와 사유 · 게이트 표
uv run python scripts/audit_scope.py --files "<축>"       # 그 축이 볼 파일 목록(위임 프롬프트에 싣는다)
python nova.py test
python nova.py lint
```
- 생성물(토큰 · k3s · 대시보드 · 대장 · 체크리스트 폼 · 출고본)은 **원천**을 감사한다. 생성물을 고치면 다음 `gen` 에 덮인다
- 이미 아는 것을 확인한다. 열린 task(`docs/plans/tasks/*.md` 의 `- [ ]`), 최근 리뷰(`docs/reviews/`), 열린 부족 항목(`warehouse.py gaps`)과 같은 것은 새 발견으로 세지 않는다
- 저장소 밖 의존(Docker · JDK · Kafka · 실제 DB)이 필요한 축은 이름을 적는다. 이 PC 에서 못 돌리면 그 축은 "판정 불가(무엇이 있으면 되는지)"로 남긴다
- 게이트 출력을 `| tail` 로 자르지 않는다 — 종료 코드를 삼킨다

**이미 게이트가 보는 것** (`python nova.py lint` · `test` — 상세는 `audit_scope.py` 표)
| 게이트 | 잡는 것 |
|---|---|
| `gen_tokens --check` | 토큰 생성물 최신 · WCAG AA 대비 50쌍 |
| `gen_k3s` · `gen_dashboards --check` · `validate_infra` | 인프라 생성물 최신 · 렌더 · Prometheus 규칙 · 대시보드 메트릭 |
| `registry check` · `ledgers --check` | 원장 · 대장 4종 최신 · 없는 API · 권한 · 역할 · 구독 · 칸 의미 |
| `packs check` | 코어 → 팩 · 팩 ↔ 팩 import 금지 |
| `docs_index --check` | 문서 인덱스 · 링크 · 문서 한글 · 표준 판정 존재 |
| `checklist check` · `warehouse check` | 체크리스트 · PRD/SPEC 스키마 · 참조 · 드리프트 |
| `python nova.py test` | 단위 · 통합 · 게이트웨이(/internal 차단 · 헤더 위조 · 권한) · 생성기 |
| `ui-smoke` · `checklist-smoke` | 웹 화면 흐름 · 체크리스트 폼(화면을 바꿨을 때) |

## 2. 축을 고르고 **한 메시지에 동시에** 띄운다
- **스킬 호출**: `superpowers:dispatching-parallel-agents`. 축 에이전트는 모두 **읽기 전용**이다(쓰기 도구가 없는 Nova 판정 에이전트 — 아래 '축 → 에이전트' 표, 맞는 것이 없으면 `Explore`). 그래서 몇 개를 띄워도 서로 방해하지 않는다. 한 건씩 부르지 않는다
- 부하에 민감한 측정(성능 · 지연)은 이 묶음에 넣지 않고 따로 돌린다. 함께 돌렸으면 결과에 "동시 부하 있었음"을 적는다
- 축 선택: `--only` 면 그 축만, `--skip` 이면 그 축을 빼고, 없으면 **범위에 실재하는 축만** 고른다. 고르지 않은 축은 **이름과 뺀 이유**를 적는다(적지 않은 면제는 면제가 아니다)

| 축 | 무엇을 묻나 (Nova 기준) |
|---|---|
| **연결성** | 서비스는 자기 DB 만 쓰는가. 서비스 사이가 이벤트(아웃박스) · `/internal` 계약 API 로만 이어지는가. `services.json` 의 라우트 · 그룹이 실제 앱과 같은가. 순환 · 고아 모듈 · 웹 → 서버 경계(`@nova/sdk` 경유)가 지켜지는가 |
| **비즈니스 로직** | 분기가 모든 경우를 덮는가. 상태 전이에 갈 곳 없는 상태 · 되돌릴 수 없는 상태가 있는가. 경계값 · 빈 입력 · 중복 요청(멱등)에서 무엇이 일어나는가. 기본 분기(`else` 끝 · `or` 기본값 · `??`)가 조용히 거짓을 만드는가 |
| **보안** | 비밀값 노출(.env · 코드 · 로그) · 주입(SQL · 명령 · 경로) · 권한 `<모듈>.<행위>` 누락 · 권한 상승 · 개인정보 노출 · 개발 로그인(`GW_DEV_LOGIN`) · 메모리 DB 의 운영 차단(`runtime`) · 저장 서버(체크리스트) 경로 탈출 · 의존성 취약점 |
| **API 계약** | 오류 봉투 `{error:{code,message}}` · 상태 코드 · 목록 계약(`paging`)이 일관한가. 파괴적 변경이 숨어 있는가. `spec.json` api · 대장과 구현이 갈렸는가 |
| **에러 처리** | 모든 외부 경계(라우트 · 소비자 · HTTP 호출 · 파일)가 실패를 명시적으로 다루는가. **삼킨 예외**(except 후 무행동)가 있는가. 소비 실패가 DLQ 로 가는가. 화면의 실패가 `useAction` · `ErrorState` 로 사용자에게 보이는가 |
| **입력 유효성** | §3 표가 정본 |
| **데이터 모델** | 기본키가 `id_column()`(UUIDv7)인가. 칸마다 `comment` 가 있는가. 다른 서비스 개체는 `ref_column`(FK 없음)인가. 인덱스 · 제약 · 마이그레이션 가역성(Alembic 전환 대비). 이름이 대장(DB 사전)과 같은가 |
| **성능** | **실측으로만** — N+1 · 페이지 없는 목록 · 번들 크기 · 렌더 비용 · 게이트 소요. 추측("느릴 수 있다")은 발견이 아니다 |
| **접근성 · 디자인 토큰** | 대비 · 포커스 · 누름 영역 · 키보드 대체 경로 · 색만으로 뜻 전달. **토큰 밖 색 · 간격 하드코딩**(`var(--color-…)` 규칙), 화면이 템플릿 + 데이터 정의를 넘는 자리. [ux-heuristics](../../docs/conventions/ux-heuristics.md) H1~H10 |
| **테스트 실효** | 초록이 무엇을 지키는가. **공허한 초록**(단언이 약하거나 대상에 닿지 않음) · 꺼진 테스트 · 고친 결함의 회귀 테스트 부재 |
| **문서 · 코드 정합** | CLAUDE.md · README · conventions · 명령(`.claude/commands`)이 단언하는 것이 코드에 실재하는가. 명령 표와 `nova.py` · 스크립트 사용법이 같은가. "막는다 · 검사한다" 표기가 실제 게이트와 같은가 |
| **표준 · 테넌시 · AX** | `nova.project.json standards` 판정과 코드가 맞는가. 테넌시 적용인데 `tenant_filter` 없는 조회 · `current_tenant()` 대신 인자로 나르는 테넌트. AX — AI 가 해서는 안 되는 쓰기에 `require_human` 이 있는가. 도메인 팩 — 코어의 업종 분기 |
| **한국어 규칙** | 코드 주석 · docstring · API 오류 메시지 · 화면 문구 · 로그 설명이 한국어인가(문서 검사는 코드를 보지 않는다). 식별자 · 명령 · 경로는 영어 그대로 |
| **생성물 · 단일 원천** | 같은 값이 원천 밖에 손으로 복제돼 있는가(포트 · 토픽 · 색 · 서비스 목록). 생성물인데 표시가 없거나 `gen` 에 빠진 것 |
| **운영 · 인프라** | k3s 자원 한도 · 준비/생존 확인 · 비밀(Secret) 취급 · NetworkPolicy 범위 · 알림 규칙이 덮는 장애 · 백업 · 되돌리기(rollback) 경로 |

### 축 → 에이전트 (`.claude/agents/`)
| 축 | `subagent_type` |
|---|---|
| 연결성 · API 계약 · 데이터 모델 · 생성물 · 단일 원천 | `contract-auditor` |
| 비즈니스 로직 · 에러 처리 · 테스트 실효 | `code-reviewer` |
| 보안 · 입력 유효성 · 표준 · 테넌시 · AX | `security-auditor` |
| 접근성 | `accessibility-auditor` |
| 디자인 토큰 | `design-token-guardian` |
| 문서 · 코드 정합 · 한국어 규칙 | `docs-auditor` |
| 운영 · 인프라 | `ops-auditor` |
| 성능(다른 축과 따로 돌린다) | `performance-engineer` |
- 같은 에이전트에 축 여럿을 줄 때도 **축마다 한 번씩 따로** 띄운다(분모가 섞이지 않게)
- 통합(§4)이 무거우면 `integrator`, 고치기(§6)는 처분 종류에 따라 `backend-developer` · `frontend-developer` · `devops-engineer` · `refactorer`, 원인 불명이면 `debugger`

### 위임 프롬프트에 반드시 싣는 것
- **분모** — `audit_scope.py --files "<축>"` 목록, 그리고 뺀 것과 이유
- **이미 게이트가 보는 것** — §1 표에서 그 축에 해당하는 줄("이것은 다시 보고하지 말 것")
- **세는 법** — 찾은 방법을 **검색으로 찾음 / 구조를 읽어 찾음 / 문서에서 찾음** 셋으로 갈라 보고하게 한다(검색만 하면 놓친다)
- **반환 4절 계약** — **핵심 답 · 실측(무엇을 몇 개 봤나) · 근거(`파일:줄`) · 미해결**. 미해결은 비우지 않는다(없으면 "없음")
- **처분은 권고로만** — 권고는 써도 되지만 판단은 메인이 한다
- **고치지 말 것** — 읽기 전용. 고치는 것은 §6
- **한국어로 보고**

## 3. 입력 유효성 축 — 무엇을 어떻게 보나 (정본)
| 대상 | 반드시 확인할 것 |
|---|---|
| 이메일 | 검증이 **한 곳**인가(정규식 복제 없음) · 대소문자 정규화 · **서버에서도**(pydantic) 검증하는가 |
| 전화번호 | 국가 번호 · 구분자 · **저장 형식이 하나**인가(표시 형식과 섞지 않음) |
| 주소 | 우편번호 짝 검증 · 자유 텍스트 길이 상한 |
| 비밀번호 | 길이 하한 · **상한이 지나치게 낮지 않은가** · 평문 기록 · 약한 해시 · **실패 메시지가 계정 존재를 흘리는가** |
| 날짜 · 시각 | 시간대(`NOVA_TZ_OFFSET_HOURS` · `fmtAt`) · 허용 범위 · 파싱 실패 시 동작 |
| 수량 · 금액 | 음수 · 0 · 상한 · **부동소수 사용 여부**(금액은 정수 · 십진) · `fmtMoney` 표시 |
| 파일 업로드 | 크기 · MIME · 확장자 **양쪽** 검증 · 경로 조작 · 저장 위치 |
| 자유 텍스트 | 길이 상한 · 이스케이프 시점 · 마크업 허용 범위 |
| 식별자 | UUIDv7 형식 검사(`is_uuid7`) · 다른 테넌트의 ID 로 접근할 때 404 |

- 세 질문을 항상 같이 묻는다: ① **있는가** ② **한 곳인가** ③ **서버에서도 하는가**(화면 검증만이면 검증이 없는 것과 같다)
- **검증 문구도 감사 대상**이다 — 무엇이 틀렸고 어떻게 고치는지 말하지 않는 오류는 사용자가 고칠 수 없다(H9 · FormPage 칸별 오류)

## 4. 통합 — 발견을 결론으로 바꾼다
1. 축 보고를 모아 **중복 제거 · 상충 표면화 · 덮지 못한 곳**을 낸다. 판정 갈래는 **확정 · 반증 · 이미 알려짐 · 범위 밖** 넷이다
   - 축을 메인이 직접 띄웠으면 보고가 이미 메인에 있으므로 메인이 통합한다. 축이 많아 컨텍스트가 위험하면 보고를 파일로 받고, `integrator` 에이전트에게 통합 요약만 맡긴다
   - 어느 쪽이든 **판정은 메인**이 한다
2. **상충은 숨기지 않는다** — 두 축이 반대로 말하는 자리가 진짜 뿌리인 경우가 많다
3. **과장을 걷어낸다** — "~할 수 있다"는 발견이 아니다. 재현 경로가 없으면 **판정 불가**로 내리고, 무엇이 있으면 판정되는지 적는다. 확정은 메인이 `파일:줄` 을 직접 읽어 확인한 것만 한다(`superpowers:verification-before-completion`)
4. 이미 알려진 것(열린 task · 리뷰 · 부족 항목)과 같으면 새로 만들지 않고 그 기록에 관측을 덧붙인다

## 5. 처분 — 다섯 갈래 중 정확히 하나
| 처분 | 언제 | Nova 에서 남기는 곳 |
|---|---|---|
| ① **즉시 고친다** | 되돌릴 수 있고 범위가 좁고, **지금 일의 종료 조건을 깨거나 치명적**이다 — 그 밖은 ② 로(plans README §5 '개선이 개선을 낳지 않게') | 고치기 전에 감사 보고에 묶음의 **목표 · 완료 조건 · 하지 않는 것**을 적는다 → §6 → 커밋 · git 기록. 고치다 새로 보인 것은 다시 고치지 않고 ② 로(한 세대 규칙) |
| ② **기록으로 옮긴다** | 고칠 것이 맞지만 이번 범위 밖 | 해당 `tasks_REQ_NN.md` 에 🆕 task(**재현 · 기대 · 실제 · 환경** + 판정 `다음 판본`), 맞는 계획이 없으면 `/req-new` |
| ③ **의도적으로 안 한다** | 알고도 안 하는 것이 옳다 | 감사 보고에 **이유**. 구조 결정이면 ADR |
| ④ **판정 불가** | 지금 재료로 참 · 거짓을 못 가른다 | **무엇이 갖춰지면 판정되는지**와 함께 보고(예: "Linux + Kafka 에서 e2e-kafka") |
| ⑤ **제안한다** | 결함이 아니라 기회 | `/req-new` 초안(근거 · 이득 · 비용 · 왜) 또는 마스터플랜 `drafts/` |

## 6. 고치기 — 되돌릴 수 있는 것만
- **고치는 것**(①만): 파일 편집 · 검증 보강 · 에러 처리 추가 · 중복 제거 · 주석 · 문서 정합
- **올리기만 하는 것**: API 계약 · DB 구조 · 마이그레이션 · 데이터 삭제 · 외부 노출 · 의존성 추가 · 권한 확대 → ⑤ 또는 사용자 확인
- 규칙
  1. **회귀 테스트를 먼저** 쓴다(`superpowers:test-driven-development` — 실패 확인 → 고침 → 통과). 원천 텍스트를 grep 하는 단언보다 **행동으로 잡는 단언**
  2. **형제를 전수로 본다** — 같은 형태가 다른 파일 · 같은 파일의 다른 함수에도 있는지 **고치기 전에** 찾는다(세는 단위는 파일이 아니라 형태)
  3. 원인이 불분명하면 추측으로 고치지 말고 `/debug`(`superpowers:systematic-debugging`)
  4. 파일이 겹치지 않으면 고치는 에이전트를 한 메시지에 함께 띄워도 된다(설계 판단은 메인이 정하고 구현만 넘긴다). 겹치면 순서대로
  5. **규모가 크면 레일로** — 5파일 이상이거나 ADR · 데이터 모델 · 계약 변경이면 여기서 고치지 않고 `/req-new` → `/plan-new`
  6. 코드와 문서를 함께 고치면, 코드가 바뀌면 거짓이 되는 문서 목록을 **착수 전에** 만든다
- 검증: `python nova.py test` · `lint`(화면이면 `ui-smoke` · 체크리스트면 `checklist-smoke`) 출력 확인 → `/review-request`(선택) → `/history-new` → 커밋 · `git_record.py`

## 7. 보고 — `docs/reviews/` 에 남긴다
`uv run python scripts/docs_new.py review "심층 감사 — <범위>"` → 아래 형식으로 채운다. 사용자에게는 요지(확정 발견 · 고친 것 · 사용자가 정할 것)만 한국어로 짧게.
```
■ 감사 분모
   범위 … · 대상 …개 · 제외 …개(사유) · 저장소 밖 의존 …
   실행한 축 … / 실행하지 않은 축과 이유 …
■ 축별 결과 (축마다)
   본 것 …개 · 발견 …건 (검색 … / 구조 … / 문서 …) · 이미 게이트가 보는 것 제외
■ 통합 판정
   확정 … · 반증 … · 이미 알려짐 … · 범위 밖 … · 상충 …(어느 축과 어느 축)
■ 처분
   ① 즉시 고침 … ② 기록(task · REQ 번호) … ③ 의도적 미실행(이유) … ④ 판정 불가(필요한 것) … ⑤ 제안(REQ 번호) …
■ 고친 것
   파일 · 무엇을 · 회귀 테스트(무엇이 되돌아가면 실패하나)
■ 남은 것
   기록 번호로 가리킨다(내용을 베끼지 않는다)
```
- 건수 · 상태를 이 보고 밖의 문서에 베끼지 않는다 — 기록(task · REQ · 리뷰)이 정본이다
- 초록을 받으면 **무엇을 몇 개 검사했는지**도 함께 본다
