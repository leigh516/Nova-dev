# 명령 빈 틀

아래 블록을 `.claude/commands/<이름>.md` 로 복사해 `<…>` 를 채운다. 기존 명령(issue · release · debug)의 모양을 따른 것이다.
- 링크는 명령 폴더 기준 — 저장소 루트가 `../../`. 틀 안의 `<… 링크 — 경로 …>` 는 채울 때 마크다운 링크로 바꾼다(이 틀 파일 자리에서는 그 경로가 실재하지 않아 링크 문법을 쓰지 않았다)
- 쓰지 않는 절은 지운다. 관문이 없는 명령이면 명령이 맞는지 다시 묻는다(스킬일 수 있다)

````markdown
---
description: <이름 풀이> — <무엇을 어떤 관문을 거쳐 끝내는지 한 문장>(<superpowers:스킬 — 있으면>)
argument-hint: <첫 인자> | <하위 동작> <인자> | status
---

# /<이름> — <이름 풀이>

인자: `$ARGUMENTS`
규칙: <정본 문서 링크 — 경로 ../../docs/…>

## 절차
0. **본 작업 트리(main)에서** — <번호 붙는 기록을 쓰는 명령이면. worktree 에서는 `python nova.py send --to main …` 으로 알린다>
1. **스킬 호출**: `superpowers:<스킬>` — <따를 단계 요지>
2. <조회 — `python nova.py <도구> …` 를 돌려 출력을 확보한다>
3. <판단 · 분기>

   | 경우 | 다음 |
   |---|---|
   | <…> | <명령 · 단계> |
4. **승인 관문**: <사용자가 무엇을 확인하기 전에는 무엇을 하지 않는다>. 승인은 <어디에 어떤 한 줄로> 남긴다
5. <실행 — 노이즈가 큰 일은 `<에이전트 이름>` 에이전트에 맡긴다(한국어 4절 보고)>
6. <검증 — `python nova.py check` 출력 확인>
7. <기록 — `/history-new` · 커밋마다 git 기록>
8. **보고** — <무엇을 한국어로 알린다>

## 멈춤
- <몇 번 실패하면 멈추고 무엇을 의심하나>
- <5분 넘는 검증 · 비싼 병렬은 크기를 먼저 말하고 확인>

## 하지 않는 것
- <이 명령의 범위 밖 일 — 새로 보인 것은 새 요구 · 다음 판본으로>
- 생성물 손 편집 · 원장 손 편집
- <worktree 에서 번호 붙는 기록 쓰기 — 해당하면>
````

## 채우기 점검
- `description` 만 읽고 언제 부를지 알 수 있는가 · `argument-hint` 가 실제 인자 모양과 같은가
- 인자 없이 불렀을 때 할 일이 있는가(목록 · 상태 · 묻기)
- 관문 문장이 "하지 않는다"로 끝나는가
- 부르는 `python nova.py …` 하위 명령 · 에이전트 이름 · `/명령` 이 실재하는가
- CLAUDE.md 명령 표 · superpowers.md 지도에 넣을 줄을 적었는가
