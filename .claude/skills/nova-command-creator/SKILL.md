# nova-command-creator — 명령 만들기 · 고치기

이름에 `nova-` 를 붙인 까닭: 전역에 일반 스킬 작성 스킬(skill-creator)이 있고 원본(psg05)의 명령 작성 스킬과도 이름이 달라야, Nova 규칙이 붙은 이 스킬과 발동이 헷갈리지 않는다.

정본은 아래이고, 이 스킬과 다르면 정본이 옳다.
- 3층 결정: [ADR-009](../../../docs/adr/ADR-009-commands-skills-agents.md) — 명령은 **절차 · 관문**
- 경계: [IDENTITY.md](../../../IDENTITY.md) '경계' — 명령의 절차 · 게이트 · 훅의 의미는 승인 없이 바꾸지 않는다(바꾸면 REQ)
- 흐름 지도: [superpowers.md](../../../docs/conventions/superpowers.md) §2 · §2.1 · 명령 표: [CLAUDE.md](../../../CLAUDE.md)
- 좋은 예: `.claude/commands/` 의 issue · release · debug(인자 줄 · 규칙 링크 · 번호 절차 · 표로 분기)

모든 문장(description · argument-hint 의 낱말 · 본문)은 **한국어**다([CLAUDE.md](../../../CLAUDE.md) 규칙 0). 명령 본문은 펼쳐지면 그대로 지시가 되므로, 영어 문장이 섞이면 응답도 영어로 미끄러진다 — Stop 훅(`.claude/hooks/persona_guard.py`)이 응답의 영어 문장을 잡는다.

## 0. 만들기 전 세 가지 — 하나라도 "아니오"면 만들지 않는다
1. 같은 절차가 **두 번 이상** 반복됐는가(세션 · 이력에서 같은 순서를 다시 쓴 흔적)
2. 기존 명령에 단계 · 하위 동작(`draft | ship` 처럼)을 더해서는 안 되는가 — CLAUDE.md 명령 표와 `.claude/commands/` 를 실제로 읽고 대조한다
3. 순서 · 관문 · 멈춤이 있는가 — 없고 판단만 있으면 명령이 아니라 스킬이다(nova-skill-creator)

## 1. frontmatter
```yaml
---
description: <이름 풀이> — <무엇을 어떤 관문을 거쳐 끝내는지 한 문장>(<쓰는 Superpowers 스킬이 있으면>)
argument-hint: <첫 인자> | <하위 동작> <인자> | status
---
```
- `description` — 한국어. `/` 목록과 자동 제안에 보이는 유일한 글이다. 첫머리에 이름 풀이, 끝내는 지점과 관문을 넣는다
- `argument-hint` — 자동완성에 보이는 인자 모양. 하위 동작이 있으면 `|` 로 나열, 자리표시는 `<…>`
- Claude Code 가 지원하는 그 밖의 키 — Nova 는 기본으로 쓰지 않는다. 쓰려면 이유를 계획에 적는다
  - `allowed-tools` — 명령이 쓸 도구를 미리 허용(예: `Bash(git status:*)`). 아래 `!` 문법을 쓸 때 필요
  - `model` — 명령 전용 모델. **쓰지 않는다**(세션 모델을 따른다 — 판본 ID 가 낡는다)
  - `disable-model-invocation` — Claude 가 스스로 이 명령을 부르지 못하게 한다. 사람만 시작해야 하는 일(릴리스 · 강제 작업)에 검토

## 2. 본문 형식
1. 제목 `# /<이름> — <이름 풀이>`
2. `인자: \`$ARGUMENTS\`` 한 줄 — 사용자가 친 인자 전체가 여기 펼쳐진다. 위치별로 나눠야 하면 `$1` · `$2` 도 쓸 수 있으나 Nova 는 하위 동작 이름으로 나누는 쪽을 쓴다(읽기 쉽다)
3. `규칙:` · `원장:` 줄 — 정본 문서 링크(링크는 `../../` 로 저장소 루트). 값 · 임계 · 개수를 본문에 옮기지 않는다
4. `## 절차` — 번호 목록, 한 단계에 한 가지. 분기는 표(`| 경우 | 다음 |`)로
5. 관문 · 멈춤(아래 3절), 부르는 도구 · 에이전트(4절)
6. `## 하지 않는 것` — 이 명령이 넓어지지 않게 막는 것(범위 밖 일 · 단일 기록자 위반 · 손 편집)
- 빈 틀: [references/template.md](references/template.md)

### Claude Code 문법 — 확인된 것만, Nova 는 아껴 쓴다
- `$ARGUMENTS` · `$1` `$2` — 인자 펼치기
- `!` + 백틱 명령 — 명령을 펼칠 때 셸을 먼저 돌려 그 출력을 본문에 넣는다(`allowed-tools` 에 해당 Bash 허용이 있어야 한다). 출력이 매번 컨텍스트를 먹고 실패해도 멈추지 않으므로, Nova 는 절차 단계 "1. `python nova.py …` 를 돌린다"로 쓴다
- `@경로` — 파일 내용을 통째로 넣는다. 큰 문서를 넣으면 컨텍스트가 무거워지므로 Nova 는 링크 + "읽는다" 단계로 쓴다
- 하위 폴더에 두면 이름공간이 생긴다 — Nova 명령은 **평면**(`.claude/commands/<이름>.md`)으로 둔다(검사기가 `/명령` 실재를 평면 기준으로 본다)

## 3. 승인 관문 · 멈춤 조건 넣는 법
- 관문은 **굵은 글씨 + 무엇을 하지 않는지**로 쓴다 — 예: "**승인 관문**: 사용자가 승인하기 전에는 코드 · 골격 · 설치를 하지 않는다. 승인은 `승인 | YYYY-MM-DD 사용자` 한 줄로 남긴다"(`/req-analyze` 형식)
- 되돌리기 어려운 단계(태그 원격 푸시 · 데이터 삭제 · 외부 공개)는 "사용자 확인 뒤"를 그 단계 안에 쓴다
- 멈춤은 숫자로 — "세 번 고쳐도 안 되면 멈추고 구조를 의심한다"(`/debug`), "5분 넘는 검증은 크기를 먼저 말한다"(IDENTITY)
- worktree 에서 돌면 안 되는 명령은 0단계에 "본 작업 트리(main)에서"(단일 기록자 — ADR-008)
- 끝이 있는 일이면 종료 조건 · 하지 않는 것을 적게 한다(CLAUDE.md '끝이 있는 일')

## 4. 명령이 부르는 것 표기
- **도구** — `python nova.py <하위 명령>` 으로 부른다(Windows · Linux 공통). 새 도구가 필요하면 `scripts/<도구>.py` 를 만들고 `nova.py` 의 COMMANDS 와 머리 도움말에 한 줄 — `nova.py` 가 다른 담당 소관이면 main 에 "넣을 연결"로 보고한다
- **스킬** — `superpowers:<스킬>` 또는 Nova 스킬 이름을 그 단계에 쓴다("**스킬 호출**: `superpowers:systematic-debugging`")
- **에이전트** — 백틱 이름으로 쓴다: "노이즈가 큰 조사는 `debugger` 에이전트에 맡겨도 된다". 검사기가 이 표기로 호출을 세고, 없는 이름이면 실패시킨다
- **병렬** — "독립 작업은 한 메시지에 함께 띄운다"와 몇 개를 띄우는지(축 · 파일 · 범위마다)를 명령이 정한다. 비싼 병렬은 "확인 후"를 붙인다
- 위임 지시에는 "한국어로 4절 보고(핵심 답 · 실측 · 근거 · 미해결)"를 넣는다

## 5. 연결 — 명령 하나 = 네 군데
| 어디 | 무엇 |
|---|---|
| `.claude/commands/<이름>.md` | 명령 본문 |
| CLAUDE.md 명령 표 | 한 줄(명령 · 내용) |
| superpowers.md §2 / §2.1 | 흐름 단계 행 또는 칸에 이름 |
| `nova.py` | 새 도구가 있으면 COMMANDS · 도움말 |
- 이 중 다른 담당 소관인 파일은 직접 고치지 않고 "메인이 넣을 연결"(파일 · 문장 초안)로 보고한다

## 6. 기존 명령을 고칠 때
- 오탈자 · 링크 · 설명 다듬기 → 바로 고치고 이력
- **절차 · 관문 · 게이트의 의미**를 바꾸는 것(단계 추가 · 삭제 · 순서 · 승인 조건) → IDENTITY 경계상 승인 없이 바꾸지 않는다. `/req-new` 로 요구를 남기고 사용자 승인 뒤 고친다
- 훅(`.claude/settings.json`)의 순서 · 의미도 같다

## 7. 시험 — 압박 시나리오 (`superpowers:writing-skills`)
- **펼침** — 예시 인자 2~3개(`<이름> <인자>` · 하위 동작 · 인자 없음)로 본문을 머릿속이 아니라 글로 펼쳐 본다: `$ARGUMENTS` 가 문장 안에서 말이 되는가, 인자 없을 때 무엇을 하는가
- **압박** — "급하니 승인 건너뛰고 바로 해" 같은 요청: 관문 문장이 그래도 멈추게 하는가
- **경계** — 이웃 명령의 일을 시키는 요청 하나: 절차가 그 명령으로 보내는가
- 결과를 보고에 한 줄씩 적는다

## 8. 검증 · 기록
```bash
uv run python scripts/claude_check.py --check
uv run python scripts/docs_index.py --check
python nova.py lint
```
- 증거 없이 "됐다"고 하지 않는다 — 출력의 오류 수를 보고에 붙인다(`/명령` · 에이전트 이름 실재는 검사기가 본다)
- 새 명령은 작업 단위 이력(`/history-new`). 흐름 체계를 바꾸는 명령(새 관문 · 새 단계 층)은 REQ · ADR — 번호가 붙는 기록은 main 만 쓴다
