# nova-subagent-creator — 에이전트 정의 만들기 · 고치기

이름에 `nova-` 를 붙인 까닭: 전역에 같은 일을 하는 일반 스킬(skill-creator 류)이 있어, Nova 규칙이 붙은 이 스킬과 발동이 헷갈리지 않게 하려는 것이다.

이 스킬은 **값을 갖지 않는다.** 정본은 아래이고, 이 스킬과 다르면 정본이 옳다.
- 편제 · 폴더 원칙 · 부르는 규칙 · '새 에이전트를 만들 때': [.claude/agents/README.md](../../agents/README.md)
- 형식 검사 규칙 전체(A1~ · 폴더 정책 · 단일 기록자 명령 목록): `scripts/claude_check.py` 머리말과 상수 — **규칙을 이 스킬에 베끼지 않는다**
- 3층 결정: [ADR-009](../../../docs/adr/ADR-009-commands-skills-agents.md) · 폴더형 편제는 ADR-010(채택되면 `docs/adr/` 에서 확인)
- 방법: `superpowers:writing-skills` · 위임 지시 작성은 [superpowers.md](../../../docs/conventions/superpowers.md) §2.1

모든 문장(description · 본문 · 반환 예시)은 **한국어**다([CLAUDE.md](../../../CLAUDE.md) 규칙 0). 식별자 · 명령 · 경로만 영어. 함께 일하는 사람은 "사용자"라고 부른다(Nova 는 플랫폼 이름).

## 0. 만들기 전 세 가지 — 하나라도 "아니오"면 만들지 않는다
1. 같은 위임이 **두 번 이상, 서로 다른 명령**에서 나왔는가 — 쓸 곳이 하나면 그것은 프롬프트다
2. 기존 정의의 description 을 조금 넓히면 되지 **않는가** — README '상황 → 에이전트' 표와 각 정의의 description 을 실제로 읽고 대조한다
3. 부를 자리(명령 문서의 단계 번호 · 스킬의 절)가 **있는가** — 안 불리는 정의는 설명이 낡고 선택 피로를 낳는다
- 판정이 애매하면 정의 대신 기존 에이전트 + 프롬프트로 한 번 해 보고, 같은 일이 또 나오면 그때 만든다(되돌림이 싸다)
- 겹침 판정을 맡기려면 `agent-creator` 에이전트(meta)에 "만들지 / 기존으로 충분한지"를 묻는다 — 이 스킬은 main 의 절차, 그 에이전트는 판정 · 초안 재료다

## 1. 폴더 고르기 (정본: README · `scripts/claude_check.py` 의 폴더 상수)
| 역할의 성격 | 폴더 | 쓰기 |
|---|---|---|
| 넓게 읽고 요약 · 입고 판독 · 외부 조사 | `research` | 읽기 전용 |
| 선택지 · 계획 · 설계 초안(본문 초안만 돌려준다) | `planning` | 읽기 전용 |
| 코드 · 테스트를 쓴다(구현 · 디버깅 · 리팩터) | `development` | 쓰기 |
| 테스트 · 게이트를 돌리거나 검토 · 감사 · 판정 | `quality` | 읽기 전용 |
| main 이 만든 파일의 본문을 채운다 | `docs` | 쓰기 |
| 운영 · 원장 · 릴리스 · 장애 | `ops` | 기본 읽기 전용(예외는 검사기 상수) |
| 에이전트 · 체계 자체를 다룬다 | `meta` | 정의 파일만 |
| 업종 지식 판정 | `domain` | **이 스킬로 만들지 않는다** |

- 도메인 팩 에이전트(`<팩>-specialist`)는 팩과 짝으로 생긴다 — `python nova.py new-pack` 또는 `uv run python scripts/packs.py agent` (틀: `packs/_template/agent.md`)
- 판정자 이름(검토 · 감사 · 시험 · 분석 꼬리말)을 쓰기 폴더에 두면 검사기가 막는다 — 이름과 폴더를 함께 정한다
- 맞는 폴더가 없으면 새 폴더를 만들지 않고 멈춘다 — 폴더 신설은 검사기 · README · ADR 을 함께 바꾸는 일이라 사용자 결정(REQ)이다

## 2. frontmatter
- `name` — 파일 이름과 같다, 소문자 · 숫자 · 하이픈, 폴더를 가로질러 유일
- `description` — 한국어, "…할 때 부른다" 같은 **호출 조건**으로 시작, 상시 자동 호출 문구 금지, 길이 범위는 검사기(A3). **마지막 문장은 경계** — "…는 X 몫이다"로 이웃 에이전트를 가리킨다
- `tools` — **반드시 명시**(생략하면 모든 도구를 물려받아 읽기 전용 경계가 문장뿐이 된다). 허용 도구 이름은 검사기 목록. 읽기 전용 자리는 쓰기 도구 없이 `Bash` 로 실측
- `model` — **쓰지 않는다**(main 을 상속). 꼭 필요하면 사용자 확인 뒤, 값은 검사기 목록 안에서
- 그 밖의 키(권한 모드 · 자동 로드 스킬 등)는 넣지 않는다 — 검사기가 모르는 키다

## 3. 본문 — 제목 + 6절 (순서 고정)
제목 `# <이름> — <역할 한 낱말>` 아래 한 문단: "너는 …다. **읽기 전용**이다(해당하면). 보고 · 생각은 한국어로 한다." 묶음은 폴더에서 파생된다 — 묶음 표지 줄을 따로 쓰지 않는다(원천이 둘이 된다).

| 절 | 쓸 것 |
|---|---|
| `## 언제 나를 부르나` | 부르는 상황 2~4개(명령 이름 · 단계 번호와 함께) + **부르지 않는 자리**(이웃 에이전트 이름) |
| `## 따르는 규칙` | 정본 링크만 — 규약 · ADR · 원장 README. 값 · 임계 · 개수 · 판본 번호를 적지 않는다 |
| `## 수행 절차` | 번호 목록. 첫 단계는 "질문을 다시 쓰고 판정 기준을 정한다", 실재 · 동작은 명령으로 잰다 |
| `## 반환 형식` | 4절 — **핵심 답 · 실측 · 근거(`파일:줄`) · 미해결**(없으면 '없음') |
| `## 하지 않는 것` | 결정 대신하기 · 범위 넓히기 · 생성물 손 편집 · 예외 삼키기 + **단일 기록자 명령 줄**(번호 붙는 기록 · 원장 · 커밋 · 푸시 — 목록은 검사기 상수, 기존 정의의 줄을 그대로 쓴다) |
| `## 실패·불확실 처리` | "없다"가 아니라 "어디를 어떤 조건으로 찾았는데 없었다", 인용과 실측을 구분, 판정 불가는 판정 불가로 |

- 단일 기록자 명령 이름은 **'하지 않는 것' 절 밖에 쓰면 lint 가 실패**한다 — 절차에 "기록은 main 에게 넘긴다"로 쓴다
- 색 값 리터럴 금지 · 상대 링크와 `/명령` 은 실재해야 한다(폴더가 한 층 깊으니 저장소 루트는 `../../../`)
- 빈 틀: [references/template.md](references/template.md)

## 4. 부르는 자리 넣기 — 정의만 만들면 끝이 아니다
1. 부를 명령 문서(또는 스킬)의 해당 단계에 백틱 이름으로 넣는다 — 예: "노이즈가 큰 조사는 `<이름>` 에이전트에 맡긴다". 안 넣으면 안 불리는 에이전트 경고(A11)
2. `.claude/commands/` · CLAUDE.md · superpowers.md §2.1 · README '상황 → 에이전트' 표가 **다른 담당 소관이면 직접 고치지 않고** "넣을 연결"(파일 · 문장 초안)로 main 에 보고한다
3. 편제표는 **생성물** — 손으로 고치지 않는다. `uv run python scripts/claude_check.py --write`
4. 새 정의는 세션이 타입 목록을 다시 읽은 뒤에 부를 수 있다 — 바로 부르면 '찾을 수 없음'이 날 수 있다

## 5. 고칠 때 (기존 정의)
- 이름을 바꾸면 부르는 명령 · 스킬도 함께 고친다(폐지 이름은 검사기 상수에 올라가 있으면 안내가 나온다)
- description 을 넓힐 때 이웃 정의의 경계 문장과 겹치지 않는지 함께 본다
- 도구를 늘리는 것(특히 쓰기 도구)은 **권한 확대** — 되돌리기 어려운 쪽으로 보고 사용자 확인 뒤에

## 6. 시험 — 압박 시나리오 (`superpowers:writing-skills`)
정의를 쓴 뒤, 예시 요청 2~3개로 **맞게 발동되고 맞게 거절되는지** 머릿속이 아니라 글로 확인한다.
- 발동해야 하는 요청 하나(예: "`/review-request` 에서 성능만 따로 보는 검토자가 필요해") — description 의 호출 조건이 이 문장을 잡는가
- 이웃과 헷갈리는 요청 하나(예: "화면 접근성 봐줘") — 경계 문장이 이웃 에이전트로 보내는가
- 만들면 안 되는 요청 하나(예: "이번 한 번만 로그 요약해 줄 에이전트") — 0절에서 멈추는가
- 결과(발동 · 경계 · 거절)를 보고에 한 줄씩 적는다

## 7. 검증 · 기록
```bash
uv run python scripts/claude_check.py --write
uv run python scripts/claude_check.py --check
uv run python scripts/docs_index.py --check
python nova.py lint
```
- 증거 없이 "됐다"고 하지 않는다 — 위 출력의 오류 수를 보고에 붙인다
- 편제를 바꾸는 일(새 폴더 · 역할 체계 · 도구 원칙 변경)은 되돌리기 어려운 체계 변경이다 → REQ · ADR. 번호가 붙는 기록은 **본 작업 트리(main)** 만 쓴다(ADR-008)
- 정의 하나 추가 · 설명 다듬기는 작업 단위 이력(`/history-new`)으로 충분하다
