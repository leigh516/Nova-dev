# 스킬 빈 틀

아래 블록을 `.claude/skills/<이름>/SKILL.md` 로 복사해 `<…>` 를 채운다. 자세한 판단 기준 · 예시는 같은 폴더 `references/<주제>.md` 로 빼고 본문에서 링크한다. 형식 규칙의 정본은 `scripts/claude_check.py` 머리말이다.
- 링크는 스킬 폴더 기준 — 저장소 루트가 `../../../`
- 틀 안의 `<… 링크 — 경로 …>` 는 채울 때 마크다운 링크로 바꾼다(이 틀 파일 자리에서는 그 경로가 실재하지 않아 링크 문법을 쓰지 않았다)
- 화면 · 토큰을 다루면 frontmatter 에 `canon: design-system` 을 넣고 값 리터럴을 쓰지 않는다

````markdown
---
name: <이름 — 폴더 이름과 같다>
description: <무엇을 한다 한 문장> — "<요청 문장 1>", "<요청 문장 2>", "<요청 문장 3>" 때 쓴다. <조회 → 하기 → 확인까지 끝내는 지점 한 문장>. <이웃 일>은 여기가 아니다(<어디 몫>).
---

# <이름> — <한 줄 원칙>

이 스킬은 **값을 갖지 않는다.** 정본은 아래 문서이고, 스킬은 순서와 판단만 준다. 정본과 이 스킬이 다르면 정본이 옳다.
- <정본 1 — 규약 문서 링크 (§)>
- <정본 2 — 원천 파일 → 생성 명령>

## 0. 조회 먼저 — 새로 만들기 전에 있는 것을 쓴다
1. <대장 · 원장 · 목록에서 같은 것이 있나>
2. <결과를 어디에 적나 — 계획서 칸 등>

## 1. 고르기
| <상황> | <고를 것> |
|---|---|
| <…> | <…> |

## 2. 하기
- <판단 규칙 — 이 저장소에만 있는 것만>
- 자세한 기준: <references 링크 — 경로 references/주제.md>

## 3. 확인
- <`python nova.py …` 검사 명령>
- 마지막에 `python nova.py check`

## 4. 출구 — 없는 것이 필요할 때
| 필요한 것 | 가는 곳 |
|---|---|
| <…> | <명령 · 원천 · 다른 스킬> |
````

## 채우기 점검
- description 의 요청 문장이 사용자가 실제로 쓰는 말투인가 · 경계 문장이 있는가
- 본문에 값 · 개수 · 판본 번호를 적지 않았는가 — 정본 링크로 바꾼다
- 본문이 한두 화면을 넘으면 references 로 뺐는가(SKILL.md 는 500줄 이하)
- 링크 · 백틱 경로가 실재하는가(검사기 S3)
