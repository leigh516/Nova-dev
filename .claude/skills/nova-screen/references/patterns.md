# 화면 판단 — 자주 틀리는 자리

규칙의 정본은 `docs/conventions/ux-heuristics.md` 다. 여기 판단이 반복해서 쓰이면 그쪽으로 올린다(이 파일은 빠른 참고).

| 상황 | 판단 | 근거 |
|---|---|---|
| 좌측 패널 | 필터가 아니라 **모드 전환**(보기 바꾸기). 필터는 목록 위 검색 · 조건 칸 | H4 일관성 |
| 계층 데이터 | 트리 위젯보다 **표 안 들여쓰기** — 정렬 · 검색이 살아 있다 | H6 기억보다 인식 |
| 설정형 화면 | 값이 없는 칸도 **빈 슬롯으로 그린다** — 무엇을 채울 수 있는지 보이게 | H6 |
| 칩 색 | **상태 = 상태 토큰**(성공 · 경고 · 위험 · 정보), **분류 = 뉴트럴** — 분류에 상태 색을 쓰면 위험처럼 읽힌다 | H2 · 색만으로 뜻 전달 금지 |
| ID · 금액 · 코드 | 고정폭 글꼴(토큰의 mono) — 자리 비교가 쉽다 | H8 |
| 되돌릴 수 있는 행위 | 확인 창 대신 실행 취소 토스트 | H3 |
| 되돌리기 어려운 행위 | 확인 창 + 무엇이 사라지는지 문장 | H5 |
| 오류 문구 | 무엇이 틀렸고 어떻게 고치는지(칸별 — FormPage `fields`) | H9 |
| 빈 목록 | 왜 비었는지 + 첫 행동 버튼(`EmptyState`) | H10 |
