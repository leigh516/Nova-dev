# nicomms 화면 판단 — 운영 콘솔에서 자주 틀리는 자리

규칙의 정본은 `docs/conventions/ux-heuristics.md` 다. 공통 판단은 [nova-screen 판단표](../../nova-screen/references/patterns.md) 가 갖고, 여기는 **원본 nicomms 가 겪은 근거**와 콘솔 고유 자리만 덧붙인다.

## 1. 골격별 판단

| 상황 | 판단 | 근거 |
|---|---|---|
| 골격 B 좌측 패널 | → nova-screen 참조(모드 전환). **덧붙임**: 고른 유형에 따라 안내 문구(`PageHeader` `description`) · 주 행동 라벨 · 행 액션 가능 여부가 **함께** 바뀌어야 한다. 좌 패널을 필터 칩으로 줄이지 않는다 — 사용자가 지금 어떤 모드인지 잃는다 | H1 상태 보이기 · H4 |
| 계층 데이터 | → nova-screen 참조(표 들여쓰기). **덧붙임**: 트리 위젯은 *탐색*이 목적일 때만(갭 C6). 대 · 중 · 소를 가로로 펼치는 관리 화면은 밀러 칼럼이 맞지만 Nova 에 없다 → 사본을 짜지 말고 출구로 | H6 |
| 골격 C 설정형 | → nova-screen 참조(빈 슬롯). **덧붙임**: 상한이 화면 자체로 보여야 한다 — 목록으로 만들면 사용자가 "왜 더 못 넣지"를 오류 문구로 배운다 | H6 · H5 |
| 골격 A 결과 헤더 | 총 건수를 표 위에 보인다(`DataTable` 페이지 응답 `total`). 등록은 `primary`, 내보내기는 `ListPage` `export`(CSV · 개인정보 열 `pii` 가림) | H1 |

## 2. 칩 · 글꼴

| 칩이 나타내는 것 | 쓰는 것 | 근거 |
|---|---|---|
| 상태(활성 · 잠김 · 정지) | `StatusBadge` + 서버 매핑의 tone → 상태 토큰 | → nova-screen 참조 |
| 분류(역할 · 유형 · 구분) | `Badge` tone `neutral` — 상태색 · 브랜드색 금지 | → nova-screen 참조 |
| 모듈 식별(어느 도메인) | `DomainTag`(도메인 식별색 1~6 — 상태색과 분리 검사) + 글자. 상태 배지 옆에서 주황 · 갈색 계열은 쓰지 않는다 | style-map G6 해소 |

- 🔴 **역할은 상태가 아니다.** 역할 칩에 위험 · 경고 톤을 주면 *경고*로 읽힌다(원본의 "거울상 위반"). *비어 있음* · *오프라인(정상 동작)* 도 오류가 아니다 — 뉴트럴
- 색만으로 뜻을 전하지 않는다 — 칩에는 늘 글자가 있다(`StatusBadge` 는 라벨을 그린다)
- ID · 사업자번호 · 금액 · 일시 · URL · 버전 · 가동시간은 mono → nova-screen 참조(고정폭 행). 포맷은 `fmtAt` · `fmtNumber` · `fmtMoney`

## 3. 확인 창 두 종류 — AI ✦ 규칙 (Nova STD-AX 와 연결)

원본은 "✦ 는 AI 산출물에만 · 일반 Confirm 은 AI 확인 카드를 대체하지 않는다"를 화면 규칙으로 두었다. Nova 에서는 이 규칙이 **STD-AX-001 등급**과 서버의 `require_human` 에 걸린다.

| 자리 | 묻는 대상 | Nova |
|---|---|---|
| 사람이 이미 누른 되돌리기 어려운 행위 | 사람에게 다시 묻기 | `useConfirm` (`useAction` 의 `confirm` 옵션) |
| 사람이 누른 되돌릴 수 있는 행위 | 묻지 않는다 | `useAction` 의 `undo` — 실행 취소 토스트 |
| AI 가 쓰기를 하려 함(STD-AX **L2** — 승인 필요) | 사용자가 아직 아무것도 안 했는데 AI 가 바꾸려 함 | **`AiConfirmCard`(C9 해소)** — 바꿀 값 전부 노출 · 취소 상시 · 일괄 실행 금지 · 드라이런(영향 건수) 먼저. 승인 API 는 서버에서 `principal(request).require_human("승인")` — 승인자 ≠ 요청한 AI |
| AI 결과 표시(L1 — 제안만) | — | 결과에 AI 산출물 표식 `AiMark`(G5 해소). **사람 콘텐츠 · 안내 배너에는 붙이지 않는다** |

- 🔴 **`useConfirm` 으로 AI 승인을 대신하지 않는다** — 둘은 묻는 대상이 다르다. 섞으면 승인 규칙이 있으나 마나가 된다. 카드가 없는 동안 L2 기능은 **화면을 내지 않거나 L1(제안만)으로 낮춘다**(STD-AX "애매하면 낮춰 잡는다")
- ✦ 는 AI 기능을 *부르는* 버튼 · AI 가 *만든* 결과에만. 장식 · 강조로 쓰지 않는다
- 화면의 확인은 *보여주는 층*이다. 감사 분리(`actor_type`) · 권한(같은 RBAC) · 실패 시 "상태 변경 없음" 알림은 *실행하는 층* — STD-AX ①②⑤ 를 계획서 §0 에서 함께 본다

## 4. 셸 · 로그인

| 상황 | 판단 | 근거 |
|---|---|---|
| 서버 상태 표시(푸터) | `StatusBadge`(상태 토큰) — 버전 · 가동시간은 mono | H1 |
| 안내 배너 | 페이지 목적 한 줄 — AI 표식 · 강조 그라데이션 금지(AI 산출물이 아니다) | H8 |
| 주소가 다른 두 로그인(플랫폼 ↔ 테넌트) | 상대편 로그인으로 가는 전환 링크는 **필수** — 잘못 들어오는 일이 상시 생긴다. 주 전환 링크 하나만 눈에 띄게, 나머지(찾기 · 저장)는 뮤트 | H9 오류에서 회복 · `LoginPage` `links`(C8 해소) |
| 넓은 콘솔 표(열이 많음) | 가로 스크롤은 표 컨테이너 안에서만 — 페이지 전체가 가로로 밀리지 않게 | H8 |
