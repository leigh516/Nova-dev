## 실행 명령
```
uv run python scripts/perf_probe.py      # 읽기 전용 · 출력만(고치기 전 · 고친 뒤 같은 조건)
```

## 출력 (핵심만 붙인다)
```
측정(단위 ms)                         고치기 전 p50/p95   고친 뒤② p50/p95
항목 상세(활동 500건, 100회)            37.33 / 233.04     18.85 / 112.55  ※
프록시(실제 TCP, 200회)                 138.51 / 409.01    25.4 / 69.41
운영 개요(가짜 Prometheus 50ms, 30회)   3169.72 / 8868.78  1079.94 / 2332.87
메뉴(200회)                             66.06 / 235.18     7.25 / 78.35
```
- 고친 뒤 ① 측정(담당의 quick 실행과 겹침)은 버리고 ②(quick 이 끝난 뒤 같은 조건)를 쓴다
- ※ ② 사이에 T04-6.03(활동 상한 50)이 들어가 상세 응답이 500건 · 29715바이트 → 50건 · 3644바이트로 바뀌었다 — 상세 수치는 연결 재사용의 효과가 아니다

## 결과
- 판정: 통과(전후 비교용) — 프록시 p50 약 5배 · 메뉴 약 9배 · 운영 개요 약 3배 빨라졌다
- 숫자: 위 표. 절대값은 쓰지 않는다 — 가짜 Prometheus · 에코 서버가 같은 프로세스 스레드라 GIL 을 나눠 쓰고 동시 부하가 겹쳐, 운영 개요가 50ms 근처가 아니라 약 1초로 나온다

## 남은 문제
- 조용한 환경에서 다시 재야 절대값을 말할 수 있다(판정 불가 — 다른 작업이 없는 PC 또는 CI 러너)
- 공유 풀은 서비스당 동시 연결 100개(httpx 기본)로 제한된다 — 운영 부하 기준 확인은 다음 판본 후보
