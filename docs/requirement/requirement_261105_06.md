## 의도 (INTENT — 해법을 적기 전에)
| 칸 | 내용 |
|---|---|
| 문제 | 템플릿으로 새 프로젝트를 만들면 정식 릴리스가 아니라 작업 중인 `main` 끝이 복사된다(v0.1.0 뒤 50커밋 · 원격 태그 0 · Release 0). 판본 번호를 올리는 기준이 없고, 마스터플랜 판본(v1.x)과 릴리스 판본(v0.x)이 서로를 가리키지 않아 "어느 계획이 몇 판으로 나갔나"를 기록으로 답할 수 없다 |
| 결과 | 새 프로젝트는 최신 정식 릴리스에서 시작하고 기준선이 판본 이름으로 남는다. 판본 번호는 규칙으로 정해지고, 마스터플랜과 릴리스가 서로를 가리키며, CHANGELOG 가 자동으로 쌓인다 |
| 영향 | `scripts/release.py` · `new_project.py` · `template_init.py` · `upstream.py` · `masterplan.py` · `docs/releases/` · `docs/conventions/` · 마스터플랜 · 복제본 |
| 제약 | 외부 도구(release-please 등)를 들이지 않는다. 원격 태그 푸시 · Release 공개 · 기본 브랜치 변경은 사람 확인 뒤 |
| 미해결 | 아래 '미결 질문' 표 |
