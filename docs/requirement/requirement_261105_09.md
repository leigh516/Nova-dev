## 의도 (INTENT — 해법을 적기 전에)
| 칸 | 내용 |
|---|---|
| 문제 | 한 계획 안의 task 진행은 `/task-run`(subagent)으로 자동이지만 ① 파일이 겹치지 않는 task 를 동시에 배치하는 규칙이 없어 직렬로만 간다 ② 세션이 끊기면 어디까지 했는지 사람이 다시 짚는다(진행 원장이 git 무시 · 자유 서술) ③ 분석 · 조사 요청이 오면 main 이 직접 처리해 구현이 멈춘다 ④ 무인으로 돌 때 고치기 고리 · 비용이 끝없이 늘 수 있고 되돌릴 시작 지점이 기록되지 않는다 ⑤ 확인 창 때문에 무인 진행이 선다 |
| 결과 | 사용자가 계획을 지정하면 main 이 task 를 겹침 없는 묶음으로 동시에 배치 · 검토 · 확인 · 체크하며 끝까지 가고, 사람 판단 자리에서만 모아서 묻고, 상한에 걸리면 멈춰 보고하고, 끊겨도 tasks 체크와 git 기록으로 이어 간다 |
| 영향 | `.claude/commands/task-run.md` · `sdd.md` · `session-start.md` · `.claude/agents/README.md` · `docs/conventions/agents.md` · `docs/conventions/superpowers.md` · (제안만) `.claude/settings.json` permissions |
| 제약 | 총괄은 main — 에이전트가 다른 에이전트를 부르는 다층 구조는 쓰지 않는다(Claude Code 는 기본 3층까지 허용하지만 Nova 는 정의 `tools` 에 Agent 를 넣지 않아 일부러 막는다 — 단일 기록자 · 판단 요청은 main 만 가능) · 사람 관문(요구 승인 · 계획 승인 · [DEEP] · 푸시 · 태그 · 의존성 · 권한 확대)은 자동으로 넘지 않는다 · 기존 명령 의미는 확장만 · 훅 의미 유지 |
| 미해결 | 없음 |

## 목적과 이유
사용자는 여러 프로젝트를 함께 굴리고, 하루 지연이 프로젝트 수만큼 곱해진다. 계획이 정해진 뒤의 반복 일(배치 · 검토 · 확인 · 체크)을 main 이 멈추지 않고 하게 해, 사람은 판단 자리에서만 들어오게 한다.
