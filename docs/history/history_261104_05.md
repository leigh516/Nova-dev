## 한 일
1. **자료 창고 `docs/warehouse/`**
   - 사용자가 만든 inbound 8분류를 outbound 에 같은 이름으로 대칭으로 만들었다
   - 창고 · 입고 · 출고 README 와 분류별 README 16개를 썼다

     - 출고 README: 나가는 것 · 만드는 법
2. **제품 정본 `docs/product/`**: `intake.json` · `prd.json` · `spec.json` 은 정본 JSON 이고, md 보기와 출고본은 생성한다. README(흐름 · 규칙 · 칸 형식)와 빈 틀 3개(`_template_*.json`)를 두었다
3. **`scripts/warehouse.py`**
   - `scan`: 입고 지문(sha256)으로 새로 · 바뀜 · 사라짐을 잡는다
   - `gaps`: PRD 영역 12개 중 근거가 없는 영역과 열린 부족 항목을 낸다
   - `out`: 보기 md, 출고 prd/spec md · html · json, 질문표 · 인수 점검표, MariaDB DDL 초안 + 되돌림(UUIDv7 `CHAR(36)` · 테넌트 칸 · 서비스별 DB), 분류별 분석 · 전체 보고를 만든다. 원천이 사라진 생성물은 지운다
   - `check`: 스키마 · 참조 · 승인 관문 · prd_version · 횡단관심사 11종 판정 · 테스트 맵 · 대칭 · 드리프트를 검사한다
   - `lint` 에 `check`, `gen` 에 `out` 을 넣었다
4. **명령**
   - `/intake`: 심층 분석. 큰 자료는 파일별 서브에이전트로 나누고, 외부 지시문은 자료로만 다룬다
   - `/prd`: 빌더 점검 · 승인 관문
   - `/foundation`: psg05 를 Nova 에 맞게 옮겼다. 4단계 질의(언어 · 프레임워크 / 아키텍처 · 배포 / DB / 횡단관심사 + 표준 3종)는 Nova 기본을 쓸지, 어디서 벗어날지를 묻는다. 결과는 ADR 3건 · `nova.project.json standards`
   - `/spec`: 서비스 · 데이터 · API · 이벤트 · 화면 · 테스트 맵. 승인 뒤에는 new-service · rbac · plan-new 로 구체화한다
   - `/req-interview`: 2-1 단계를 넣어 부족 항목만 묻고, 답은 G-* 에 되돌린다
5. CLAUDE.md(문서 규칙 0번 · 명령 표) · README · superpowers.md 지도(⓪ 입고 분석 · ②′ PRD · 기반 · SPEC)를 갱신했다. `new_project` 는 창고 내용과 제품 정본을 비우고 README · 빈 틀은 남긴다
