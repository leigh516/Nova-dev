# ADR-009 · 명령 · 스킬 · 에이전트 3층 작업 체계

| 항목 | 내용 |
|---|---|
| 일자 | 2026-11-04 |
| 상태 | 채택 |
| 대체 | - |
| 요구 | [REQ-261104-13](../requirement/requirement_261104_13.md) |

## 배경
- Nova 에는 명령(`.claude/commands/`)만 있었다. 그래서 흔한 일에 정해진 길이 없었다.
  - 해당하는 일: 운영 결함 · 긴급 수정 · 변경 요청 · 교훈 · 상류 판본 받기 · 화면 조립.
  - 기능별 전문가를 부를 이름도 없어서, 위임할 때마다 프롬프트를 새로 썼다(general-purpose · Explore).
- psg05 는 명령 50 · 스킬 14 · 에이전트 42 를 갖췄다. 다만 대부분이 psg05 고유 경로(`docs/state` · `.mjs` · pnpm)와 브랜드에 묶여 있다.
- 그대로 복사하면 Nova 에서 "판정 불가"가 쏟아지고, 에이전트가 너무 많아 무엇을 부를지 모르게 된다.

## 결정
세 층으로 나누고, 층마다 맡는 것을 정한다.

| 층 | 맡는 것 | 위치 | 이번에 들인 것 |
|---|---|---|---|
| 명령 | **절차** — 사용자가 부르는 일의 순서와 관문 | `.claude/commands/*.md` | issue · hotfix · postmortem · learn · change · sync-upstream · worktree-sync + 기존 18개 보강 |
| 스킬 | **판단 묶음** — 요청 문장으로 자동 발동되는 방법 | `.claude/skills/<이름>/SKILL.md` | nova-screen · nova-ui-verify · nova-masterplan |
| 에이전트 | **역할** — 명령이 정한 자리에서 부르는 전문가 | `.claude/agents/*.md`(평면) | 핵심 편제(조사 · 설계 · 구현 · 검증 · 판정 · 기록 — 목록은 편제표 `.claude/agents/README.md`) + 도메인 팩마다 `<팩>-specialist` |
| 도구 | 판정 · 기록의 기계 부분 | `scripts/*.py` → `python nova.py …` | check · progress · issue · impact · learn · upstream · worktree-sync |

규칙은 다음과 같다.
- **오케스트레이션은 main 하나가 한다.** 에이전트는 재료를 내고, 판정 문장은 main 이 쓴다.
- **병렬은 명령이 정한 자리에서만 띄운다.** 해당하는 자리: `/deep-audit` 축 · `/intake` 파일 · `/review-request` 범위. 비싼 병렬은 확인한 뒤에 띄운다(IDENTITY).
- **판정자는 쓰기 도구를 갖지 않고, 조사 · 판정자는 Bash 로 실측한다.**
- **번호가 붙는 기록 · 원장 · 커밋 · 푸시는 main 만 한다**(단일 기록자 — ADR-008). 에이전트 정의의 '하지 않는 것' 절 밖에 이 명령들이 나오면 lint 가 실패시킨다.
- **반환은 4절이다** — 핵심 답 · 실측 · 근거(`파일:줄`) · 미해결.
- **스킬은 값을 갖지 않는다.** 정본(ui.md · 토큰 · plans README)을 가리킨다. `canon: design-system` 스킬에는 색 · px · 비율 리터럴을 쓰지 않는다.
- **형식은 `scripts/claude_check.py` 가 lint 에서 검사한다.** 에이전트 편제표(`.claude/agents/README.md`)는 그 도구가 만드는 생성물이다.
- `new-project` 는 `.claude/` 를 통째로 물려준다. 복제본은 `/sync-upstream` 으로 공통부(`scripts/upstream.py` 의 목록이 정본)를 받는다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| psg05 42개 에이전트를 그대로 | 빠짐이 없다 | 고유 경로 · 원장이 없어 판정 불가, 선택 피로 | Nova 규모와 스택에 맞지 않음 |
| 에이전트 없이 명령 프롬프트만 | 파일이 적다 | 위임마다 지시를 새로 씀, 도구 권한 경계가 문장뿐 | 읽기 전용 경계를 기계로 지키지 못함 |
| 스킬로 모두(명령 · 에이전트 대신) | 자동 발동 | 관문 · 순서가 흐려짐 | 승인 관문이 있는 일은 명령이어야 한다 |
| 칸반 · 관제 · 회차 분할 · rewind 들이기 | 대규모 병렬 관측 | 운영 비용이 큼 | 하지 않는 것으로 둔다(REQ-261104-13) |

## 결과
- **좋아지는 것**
  - 흔한 일마다 부를 이름이 하나씩 생긴다(명령 · 스킬 · 에이전트).
  - 읽기 전용 · 단일 기록자 · 한국어 규칙을 lint 가 지킨다.
  - 복제본이 첫날부터 같은 체계를 갖는다.
- **감수하는 것**
  - 정의 파일이 늘어난다(에이전트 · 스킬 — 개수는 편제표가 정본).
  - 명령 문서가 에이전트 이름을 부르므로, 이름을 바꾸면 명령도 함께 고쳐야 한다(lint A11 이 잡는다).
- **이후 규칙**
  - 새 에이전트를 만들기 전에 "기존 편제로 안 되나"부터 묻는다.
  - 새 스킬 · 에이전트는 `superpowers:writing-skills` 원칙을 따르고 `claude_check.py --check` 를 통과해야 한다.
