# ADR-004 · 대장 형식 — 이력 JSONL · 선언과 상태 JSON · 보기 MD

## 배경
project-start-guide-05 의 `registry/` 는 화면 · DB 사전 · 권한 · 이벤트 대장을 **MD 표**로 두고, 표 안 `<!-- derive:begin -->` 구간을 생성기가 채우며 **MD 표를 파서로 다시 읽는다**(열 순서 · 개수 고정, `(예시)` 행 건너뛰기 같은 "파서 계약"). 그 저장소 스스로 링크 17건이 썩고, 형식 절이 실물과 달랐던 사례를 기록했다. Nova 는 이미 생성물 원장을 **JSONL 이벤트 → JSON 스냅샷 → MD 보기**로 운영한다. 대장 4종을 들이며 무엇을 어떤 형식으로 둘지 정해야 한다.

## 판단 기준
| 성질 | MD | JSON | JSONL |
|---|---|---|---|
| 사람이 읽기 | 가장 좋음 | 보통 | 나쁨 |
| 기계가 읽기 · 검증 | 나쁨(표 파서 필요, 열 순서에 깨짐) | 좋음(스키마 검사) | 좋음 |
| 사람이 손으로 고치기 | 좋음 | 보통(구조 강제) | 나쁨 |
| 추가 전용 이력 · git 병합 | 나쁨(표 중간 수정 충돌) | 나쁨(한 문서 전체가 한 값) | **가장 좋음**(한 줄 = 한 사건, 끝에만 붙음) |
| diff 리뷰 | 좋음 | 좋음(정렬 · 들여쓰기 고정 시) | 좋음 |

## 결정
**정본은 하나, 형식은 용도별로.** 같은 정보를 두 형식으로 손으로 적지 않는다(재입력 금지).

| 용도 | 형식 | 파일 | 누가 쓰나 |
|---|---|---|---|
| **변경 이력**(생성 · 이동 · 삭제 · 복원 · 이름 변경) | **JSONL** | `registry/events.jsonl` | `registry.py sync` 만(추가 전용) |
| **사람이 정하는 정본**(역할 · 권한 표, 표준 판정, 대장 스캐너 설정) | **JSON** | `services/gateway/gateway/rbac.json` · `nova.project.json` `standards` · `registry/registry.config.json` | 사람(리뷰 대상) |
| **기계용 현재 상태**(원장 스냅샷 · 대장 4종) | **JSON**(생성) | `registry/registry.json` · `registry/ledgers.json` | 생성기만 |
| **교훈 원장**(트리거 → 규칙 · 승급 · 폐기 — REQ-261105-02 로 이전 예정) | **JSONL** 원천 + **MD**(생성) 보기 | `docs/memo/lessons.jsonl` → `docs/memo/lessons.md` | `lessons.py` 만(추가 전용) — 이전 전까지는 MD 가 원천인 예외 |
| **사람용 보기** | **MD**(생성) | `docs/registry/README.md` · `screens.md` · `db-dictionary.md` · `permissions.md` · `events.md` | 생성기만 — **파서가 MD 를 다시 읽지 않는다** |
| **원천이 코드인 것** | 코드 | SQLAlchemy 모델(컬럼 · `comment`) · FastAPI 라우트 · `svc.emit` / `@svc.on` · 웹 `api(…)` 호출 · `kafka-topics.txt` | 개발자 |

- **대장 4종은 코드에서 파생**한다(psg05 원칙 "실물이 이긴다"): DB 사전 = SQLAlchemy 메타데이터, 이벤트 = 토픽 카탈로그 + 발행/구독 스캔, 권한 = 서비스 권한 모듈 × 라우트 행위 + 역할 표, 화면 = 웹 화면 파일이 부르는 API → 그 API 를 가진 서비스 → 그 서비스의 표
- 화면의 이름 · 진행 상태처럼 코드에서 알 수 없는 것만 화면 파일 머리 주석 `@screen 이름 · @status 기획|설계|개발|완료` 으로 **선언**한다(계약이 선언하고 도구는 읽기만)
- 생성물은 `--check` 로 지킨다(lint). 대장끼리의 정합(없는 API 를 부르는 화면, 역할 표에 없는 권한을 쓰는 메뉴, 구독자 없는 토픽)도 lint 가 검사한다

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| psg05 방식(MD 표가 정본 + 파서) | 열 순서 · 표 모양에 기대는 파서는 깨지기 쉽고, 사람이 고친 표와 생성 구간이 섞여 정본이 둘이 된다 |
| 전부 JSONL | 사람이 정하는 선언(역할 표)을 사건 로그로 쓰면 현재 값을 알기 어렵다 |
| 전부 JSON | 이력이 한 파일 전체 값이라 병합 충돌 · 감사 추적이 어렵다 |
| YAML 선언 | 주석이 편하지만 생태계가 이미 JSON(nova.project.json · services.json · DTCG 토큰)이라 형식을 늘리지 않는다 |

## 결과
- 좋아지는 것: 사람은 MD 로 읽고, 기계는 JSON 으로 검사하고, 이력은 JSONL 로 남는다. 손으로 두 번 적는 곳이 없다
- 감수하는 것: 대장 생성기가 서비스 모델을 import 한다(테스트용 메모리 DB 로)
- 이후 규칙: 새 대장 종류는 이 표에 형식을 정하고 추가한다. MD 를 기계 입력으로 쓰지 않는다
