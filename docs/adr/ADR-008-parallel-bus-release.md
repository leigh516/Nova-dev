## 배경
- 사용자는 project-start-guide-05(psg05)가 너무 복잡해 개발 시간이 많이 든다고 보고 Nova 를 다시 만들고 있다. 우선순위는 **신속성 · 효율성**이다
- psg05 에서 다음 다섯을 채택하기를 원했다
  - 버전 릴리스
  - 공통 영역이 끝나기 전 병렬 진입 금지
  - 메시지 버스
  - 목표 · exit · 하지 않는 것(무한 진화 방지)
  - worktree 병렬 개발 + 버스 통신
- 마스터플랜 판본 관리의 개선점도 확인하기를 원했다
- 분석 결과 다섯 기능의 핵심은 작다. psg05 는 기능마다 1,300~3,500줄 스크립트로 커졌고(스크립트 276개 · 14.5만 줄), 그 대부분이 예외 처리 · 사건 기록이다. psg05 스스로 한 회차 커밋 중 제품 코드가 8.8% 였다고 쟀다

## 결정

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| psg05 스크립트를 그대로 옮김 | 검증됨 | 수만 줄 · Node · 복잡도가 개발 시간을 잡아먹음 | 사용자가 문제로 본 바로 그것 |
| GitHub PR · 이슈로 소통 | 외부 도구 | 원격 · 권한 · 느림, 혼자 + Claude 세션 병렬에 과함 | 로컬 파일 버스가 빠르다 |
| 병렬 게이트 없이 worktree 자유롭게 | 빠른 출발 | 공통부를 각자 고쳐 병합이 지옥이 된다 | 사용자가 명시적으로 막기를 원함 |

## 결과
- 좋아지는 것
  - 공통 기반이 선 뒤에만 병렬로 가고, 묶음 경로가 겹치지 않아 병합이 쉽다
  - worktree 세션끼리 파일로 바로 소통한다
  - 요구 · 판본 · 릴리스가 종료 조건으로 끝나고, 새 발견은 다음으로 간다
  - 지난 마스터플랜이 몰래 바뀌지 않는다
- 감수하는 것
  - 경로 겹침 검사는 글롭 접두어 비교라서 대략적이다 → 필요해지면 대장(소유 표)으로 보강한다
  - 버스는 로컬 파일이라 다른 PC 와는 공유하지 않는다
- 지킬 것
  - 게이트 표의 '완료'에는 증거가 있어야 한다
  - worktree 에서 번호 기록을 쓰지 않는다
  - 소진형 종료 조건을 쓰지 않는다
  - 지난 판본을 고치지 않는다(새 초안으로)
