# ADR-012 · 이벤트 중복 제거 키 · 권한 원천 장애 503 · AI 쓰기 범위

| 항목 | 내용 |
|---|---|
| 일자 | 2026-11-04 |
| 상태 | 채택 |
| 대체 | - |
| 요구 | [REQ-261104-11](../requirement/requirement_261104_11.md) P1 · P4 · P10 · 계획 [plan_REQ_03](../plans/plan_REQ_03.md) |

## 배경
- **P1** 소비 측 중복 판정은 이벤트 id 로 한다(`service.py` `_consume`). 그래서 같은 업무 사건이 다른 이벤트 id 로 두 번 오면 두 번 처리된다. 그런데 기본 `idempotency_key` 는 `{source}:{topic}:{key}` 로 집계마다 같아, 그대로 중복 제거 키로 쓰면 같은 집계의 두 번째 이벤트가 조용히 버려진다(예: 키를 고정해 내는 권한 무효화).
- **P10** 권한 원천(rbac) 장애일 때 게이트웨이가 403 `rbac_unavailable` 을 낸다. 사용자에게는 '권한 없음'으로 보여 원인을 잘못 읽게 한다.
- **P4** AI 행위자는 영구 삭제만 막혀 있다. STD-AX L1 은 'AI 는 초안까지, 저장은 사람'이다.

## 결정
- **P1 중복 제거 키** — 기본값을 `{source}:{topic}:{key}:{event_id}` 로 바꾼다(이벤트마다 다르다). 업무 단위 중복 제거가 필요하면 `emit(..., idempotency_key=…)` 로 **명시**한다. 소비 판정은 (consumer, idempotency_key) — 칸이 빈 옛 행은 event_id 로 대체 판정한다.
  - 단계: Expand(칸 · UNIQUE 추가) → Migrate(기록 · 판정 전환) → **Contract 는 다음 판본**(처리 기록 보관 기간 14일이 지나 빈 칸 행이 0 일 때 대체 판정 제거 · NOT NULL)
- **P10** — 권한 원천 장애는 **503 + `Retry-After`**. fail-closed 는 그대로다(상태 코드만 의미대로). 웹 · KMP 가 먼저 두 상태를 모두 '잠시 뒤 다시 시도'로 보이게 하고(Expand), 게이트웨이를 바꾼 뒤(Migrate), 웹의 옛 분기를 지운다(Contract). KMP 는 배포된 앱 때문에 옛 분기를 남긴다.
- **P4** — 샘플 · 템플릿의 **모든 쓰기**(생성 · 수정 · 보관 · 보관 해제 · 삭제)에 `require_human`. 감시 테스트가 쓰기 처리기마다 확인한다.
- **D3 칸 이름**(플랫폼 표) — `outbox.parked → is_parked` · `processed_event.ok → is_ok` · `processed_event.at → processed_at` 를 이번 마이그레이션에서 바꾼다(명명 규약 baseline 3건 삭제). 기본키 2건(outbox INTEGER 순번 · processed_event 복합키)은 발행 순서 · 멱등 설계라 **의도한 예외**로 명명 규약에 옮긴다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| 기본 키를 그대로 중복 제거 키로 | 변경이 적다 | 같은 집계 두 번째 이벤트 손실 | 데이터 손실 |
| 중복 판정을 event_id 로 유지 | 지금 그대로 | 같은 업무 사건 재발행을 못 막음 | P1 수용 기준 |
| rbac 장애를 403 유지 + 문구만 | 계약 변경 없음 | 클라이언트가 원인 · 재시도를 판단 못 함 | 상태 코드가 거짓말 |
| AI 쓰기는 삭제만 막기 | 지금 그대로 | L1 과 어긋남 | 표준 판정 위반 |

## 결과
- **좋아지는 것**: 중복 제거가 업무 의미로 동작하고 손실이 없다 · 장애와 권한 없음이 구분된다 · L1 이 코드로 강제된다
- **감수하는 것**: 처리 기록 칸 1개 추가 · 외부 클라이언트의 403 분기 수정 필요(Expand 로 완화) · AI 초안 기능은 사람 저장 단계가 꼭 있어야 한다
- **이후 규칙**: 업무 키 중복 제거는 명시 키로 · 새 서비스 쓰기 처리기는 `require_human` 을 부른다(감시 테스트)
