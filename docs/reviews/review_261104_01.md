## 1. 총평
- 공통 라이브러리의 핵심(아웃박스 원자성 · 재시도 → DLQ · JWT)은 단단했다
- 구멍은 세 경계에 몰려 있었다
  - **운영 배포의 다른 길**: Helm 경로는 운영 안전장치가 꺼진 채로 뜬다
  - **게이트웨이의 경로 해석**: 인코딩한 점 경로로 차단을 우회한다
  - **기본 분기의 조용한 거짓**: 아웃박스 머리 막힘 · 개발 DLQ 폐기 · 오류 봉투 밖 응답 · 팩 포트 오타
- 독립된 담당 2곳 이상이 같은 것을 짚은 자리(★)가 8곳이었다. 셋이 함께 짚은 Helm 이 가장 깊은 뿌리였다
- 테스트는 초록이지만 게이트웨이 권한 분기 · 대비 검사 · 저장 서버에 공허한 곳이 있었다

### ④ 판정 불가 (무엇이 갖춰지면 판정되나)
- 점 경로 우회가 운영 인그레스(Traefik)에서도 되는가 → k3s 배포 뒤 `curl --path-as-is`

- compose Prometheus 의 쿠버네티스 탐색 설정 로드 → `docker compose up`(T01-4.08)
- 웹 단위 테스트 없음(화면은 스모크로만) → 브라우저 실행 환경에서 판단

- 새 404: 끝 `/` · `//` 주소도 게이트웨이가 404 로 돌린다(웹 코드에 없음 확인)

- 템플릿에 삭제 API 는 넣지 않았다(새 서비스마다 삭제 권한이 생기는 설계 변경) — 안내 주석만
