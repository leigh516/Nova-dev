# inbound/checklist — 요구 체크리스트 (입고 · 읽는 순서 1)

> 한 줄 요약: 고객이 **클릭으로** 요구를 고르는 폼 `checklist.html` 과 고객이 돌려준 답(`checklist_YYYYMMDD_NN.json` + 읽기 쉬운 `.md`)을 두는 곳이다. 다른 입고 자료를 역으로 분석해 **폼을 미리 채워** 만들고, 고객은 확인하고 부족한 것만 더 채운다. 명령: `/checklist` · `python nova.py checklist` · 요구: [REQ-261104-03](../../../requirement/requirement_261104_03.md)

## 여기에 있는 것
| 파일 | 무엇 | 누가 만드나 |
|---|---|---|
| `checklist.html` | **입력 폼** — 파일 하나로 열린다(외부 스크립트 없음 · 밝은/어두운 화면 · 휴대폰). 자료에서 채운 답이 미리 들어 있다 | `uv run python scripts/checklist.py build` (생성물 — 손으로 고치지 않는다) |
| `checklist_YYYYMMDD_NN.json` | **고객 답 정본** — 폼의 [임시저장] · [완료하고 제출]이 만든다 | 고객(폼) |
| `checklist_YYYYMMDD_NN.md` | 같은 내용을 사람이 읽기 쉽게 — 계층 들여쓰기 · 채울 것 · 표준 판정 후보 | `checklist.py md` 또는 저장 서버(생성물) |

- 질문 트리 정본은 `scripts/checklist_form/tree.json` 하나다. 질문을 늘리려면 거기에 한 줄을 더하고 `checklist.py build` 를 돌린다. 섹션 · 질문 수는 이 문서에 적지 않는다(트리가 답이다)
- 자동 채움 정본은 `docs/product/checklist_prefill.json` 이다. 답마다 근거(입고 분석 발견 `E-*`)가 있어야 한다
- 폼과 md 는 이 폴더에 있어도 **입고 자료로 분석하지 않는다**(생성물 표시로 걸러진다). 분석 대상은 고객이 준 json 이다

## 폼 쓰는 법 — 복잡하지 않게
- **클릭으로 고른다**: 보기를 누르면 그 보기의 **세부 질문이 바로 아래에 펼쳐진다**(예: "외부 고객" → "회원가입이 필요한가요?"). 고르지 않은 보기의 세부 질문은 보이지 않는다
- **설명을 보며 고른다**
  - 보기마다 한 줄 설명(어떤 경우에 맞는지)과 ⚠ 주의(비용 · 제약)가 붙는다
  - `Nova 기본` 배지는 Nova 에 이미 준비된 선택으로, 고르면 공통 부품을 그대로 쓴다. `권장` 배지는 대부분의 경우 무난한 선택이다
  - 질문마다 **[쉬운 설명]**(비유로 푼 해설)을 펼칠 수 있고, 글 칸에는 예시가 들어 있다
  - 어려운 말은 머리의 **[용어 풀이]**에서 찾는다(찾기 칸 있음)
- **답하기 어려우면 스위치로 넘긴다**
  - 질문 오른쪽 **[건너뛰기]** 스위치를 켜면 그 질문을 넘긴다
  - 섹션 머리의 **[이 섹션 답하기]** 스위치를 끄면 그 섹션 전체를 넘긴다(원본의 섹션 포함 스위치와 같다)
  - 넘긴 것은 진행률에서 빠지고, 받은 뒤 부족 항목이 되어 나중에 인터뷰로 묻는다
- **자료에서 채운 답**: 노란 "자료에서 채움 · 확인 필요" 배지와 근거가 함께 보인다. 맞으면 [맞아요], 틀리면 다른 보기를 누른다
- **단계 — 기본 / 자세히 / 전문가**(누적)
  - 처음에는 기본 질문만 보인다 — 무엇을 만들지
  - [자세히]는 화면 · 기술 선택 · 공통 기능 · 로그인 · 디자인 같은 "어떻게"를 더한다
  - [전문가]는 이름 · 경계 규칙 · 개발 환경 · 라이선스 · 출하 같은 "계약 · 운영"을 더한다
  - 낮은 단계로 작성한 문서에 높은 단계 질문이 비어 있는 것은 **빠뜨림이 아니라 범위 밖**이다. 단계를 낮춰도 이미 답한 것은 지워지지 않는다
- **기술 선택**("자세히" 단계): 화면 · 서버 · 앱 기술, 서버 구조, 배포, DB, 마이그레이션의 **모든 선택지를 설명과 함께** 보여 준다
  - Nova 기본에서 벗어나면 무엇을 직접 만들어야 하는지 ⚠ 로 알린다
  - 이 답은 `/foundation`(기반 설계)의 입력이 되고, 질문에 `기술 결정` 배지가 붙는다
  - **공통 기능** 11종(인증 · 권한 · 화면 틀 · 디자인 · 오류 · 기록 · 감시 · 이벤트 · 목록 · 다국어 · 파일)은 [Nova 내장 / 직접 / 안 씀] 중에서 고른다
- **표로 적는 질문**(예: 만들 화면 · 기능 목록): 한 줄씩 적으면 빈 줄이 하나 더 생긴다. [지우기]로 줄을 뺀다
- **디자인 섹션** — 섹션 위의 **미리보기 화면**에 고른 값(색 · 밝기 · 모서리 · 밀도 · 글꼴 · 글자 크기 · 메뉴 배치 · 목록 모양 · 문구 말투)이 바로 반영된다
  - **표준 디자인 킷**(`design.kit`, 기본 단계 · 섹션 맨 앞 — REQ-261106-04): 킷은 색 · 모서리 · 간격 · 밝기 값을 한 벌로 묶은 것이다
    - 보기는 tree.json 에 적지 않는다 — `checklist.py build` 가 킷 목록 정본 `design/tokens/kits/catalog.json` 에서 채운다(질문의 `options_from: "kits"`). 킷을 더하면 `build` 만 다시 돌린다
    - 보기마다 그 킷의 견본(분위기 견본과 같은 모양)이 붙고, 고르면 위 미리보기가 그 킷의 브랜드 색 · 모서리 · 간격 · 밝기로 바뀐다(낱개 질문에 답한 값이 있으면 그 값이 이긴다). Nova 에 아직 없는 부품이 있는 킷에는 ⚠ 로 개수를 알린다
    - `checklist.py check` 가 킷 목록을 검사한다: 목록이 있고 기본 킷 `nova` 가 있는지 · 갭이 '화면 부품 — Nova 에 없는 부품'(`parts.need`) 보기 ID 인지 · 토큰 파일이 있는지
    - md 의 `## 디자인 결정` 맨 앞에 **킷 결정** 줄(고른 킷 · Nova 에 없는 부품)이 붙는다
    - **제출(완료)본을 `checklist.py import` 하면 실제로 설정된다** — `scripts/kits.py` 의 `use`(= `python nova.py kit use <id>`, 대비 검사 통과 킷만)를 부르고, `nova.project.json` `design.origin` 에 `checklist:<파일>#design.kit` 출처를 남긴다. 목록에 없는 킷 · 검사에 걸린 킷은 설정하지 않고 부족 항목으로 올린다. 킷의 부품 갭도 부족 항목이 된다
    - 체크리스트로 설정된 킷은 `/foundation` 5단계에서 확인하고, 바꾸려면 `python nova.py kit use <id>` 로 다시 설정한다
  - **색 고르기**(메인 · 보조): ① 업종별 **색 견본**을 누른다 ② **[직접 지정]** 에서 색 선택기를 쓰거나 HEX 코드(예: `#2563EB`)를 넣고 Enter ③ **[세밀하게 조정]** 의 색상 · 채도 · 밝기 막대로 맞춘다
  - 고른 색마다 버튼 · 링크 글자 · 어두운 화면 글자 미리보기와 **명도 대비(WCAG AA 4.5:1) 통과/미달**이 보인다. 미달이면 같은 계열의 **글자용 진한 색**을 자동으로 제안하고, 그 값(`text_hex`)도 함께 저장한다
  - 모서리 · 밀도 · 그림자 · 글꼴 · 글자 크기 · 메뉴 배치 · 목록 모양 · 아이콘 · 문구 말투 보기에는 작은 미리보기가 붙는다
  - 그 밖에 묻는 것: 상태 색 · 로고 · 밝기 전환 허용 · 머리 구성 · 첫 화면 · 그래프 · 사진/일러스트 · 움직임 · 좋아하는/싫어하는 디자인 · 접근성
  - **전체 분위기**(자세히): 업무형 깔끔 · 미니멀 · 신뢰형 · 친근 · 프리미엄 · 관제 · 데이터 밀집 · 공공(KRDS 참고) — 보기마다 작은 견본이 붙는다. 견본의 브랜드 색만 데이터의 HEX(색 견본과 같은 방식)이고 바탕 · 선 · 모서리 · 간격은 토큰 변수다(`checklist.py check` 가 견본 값을 검사)
  - **모양 · 표시**: 입력 칸 배치 · 브랜드 낱말 · 최대 화면 폭 · 버튼 · 입력 칸 · 표 · 카드 모양 · 회색 톤 · 그래프 색 · 아이콘 묶음 · 불러오는 중 표시 · 알림 위치 · 날짜 · 금액 · 숫자 표시 형식(대부분 전문가 단계 — 기본 단계는 늘리지 않는다)
  - 답은 md 의 `## 디자인 결정` 절로 모이고, `design/tokens/brand.tokens.json`(디자인 토큰)에 반영한 뒤 `python nova.py tokens` 로 대비를 다시 검사한다
  - **디자인을 어디서 가져올지**도 고른다
    - Nova 기본 · 표준 디자인 킷(위 `design.kit` 에서 고른 킷) · 우리가 준 목업
    - 널리 쓰는 디자인 시스템 참고(Material · Apple HIG · Ant · shadcn/ui · 토스 · Carbon · KRDS 정부)
    - 참고 사이트 · Figma 시안
    - **AI 디자인 도구(스킬)로 시안 제안**(impeccable · theme-factory · design-critique · accessibility-review)
    - 외부 디자인은 베끼지 않고 토큰으로 옮겨 대비 검사 · 라이선스 확인을 거친다
- **목업 · 기존 화면 채택** — `inbound/html-mockup`(화면 파일) · `inbound/screenshot`(캡처)에 넣은 것이 목록으로 나온다
  - 저장 서버로 열면 넣자마자 보이고, 파일로 열면 `checklist.py mockups` → `build` 후에 보인다
  - 목업마다 [열어 보기]로 확인하고 **채택 수준**(그대로 채택 · 화면 배치만 · 디자인만 · 기능 · 흐름만 · 참고만 · 채택 안 함)과 메모를 남긴다
  - 이어서 고르는 것: 목업에 없는 화면을 어떻게 만들지, 목업의 색 · 글꼴을 토큰으로 옮길지, 그대로 가져올 동작, 목업에 없지만 꼭 필요한 것
  - 저장 서버는 이 두 폴더의 파일만 읽기 전용으로 보여 준다(폴더 밖은 막음)
- **화면 부품** — 분류별(틀 · 버튼 · 입력 · 목록 · 표시 · 피드백 · 차트 · 도움말)로 묶어 보인다

  - **Nova 에 없는 부품**: 입력 · 선택(날짜 · 기간 · 태그 · 슬라이더 …) · 목록 · 표(엑셀 올리기/내려받기 · 칸에서 고치는 표 · 저장된 필터 · 권한 표 …) · 화면 구성(탭 · 아코디언 · 드로어 · 명령 팔레트 …) · 일정 · 시간 · 소통 · 업무(결재선 · 조직도 · 댓글 · 변경 이력 …) · 보기 · 미디어로 묶어 요청하거나 직접 설명한다

  - 머리의 [Nova 보기] 버튼이나, 보기 옆의 [보기 ↗]를 누르면 열린다
  - 카드 15개: Nova 기본이란(좋은 점 · 알아 둘 점) · 디자인 · 화면 틀 · 목록 · 입력 · 상세 · 로그인 · 확인 창 · 되돌리기 · 배지 · 숫자 카드 · 빈 화면 · 스위치 · 단축키 · 기술

- **[채울 것만]** 은 비었거나 확인 전인 질문만 모아 보여 준다. **[요약 보기]** 는 고른 답을 계층으로 보여 준다

## 임시저장하고 이어가기
| 버튼 · 기능 | 하는 일 |
|---|---|
| 자동 저장 | 고를 때마다 이 브라우저에 저장된다(머리에 "자동 저장 시각" 표시). 창을 닫았다 다시 열면 그대로 이어진다. 폼을 다시 만들어도(자동 채움이 바뀌어도) 이미 답한 것은 남는다 |
| **[임시저장]** | 작성중(draft)으로 파일을 남긴다. 저장 서버면 `inbound/checklist/` 에 바로 기록하고, 파일로 열었으면 json 을 내려받는다. 같은 세션에서 다시 저장하면 같은 파일을 덮고 판이 오른다 |
| **[불러오기]** | 다른 PC · 다른 브라우저에서 이어 쓸 때. 저장 서버면 최신본을, 파일로 열었으면 고른 json 을 불러온다 |
| **[완료하고 제출]** | 완료(complete)로 저장한다. 빈 것이 있으면 한 번 묻는다. 제출 뒤 고치면 작성중으로 돌아간다 |

## 작성중인 것은 반영하지 않는다
| status | 뜻 | 요구 분석(`/intake` · `checklist.py import`) |
|---|---|---|
| `draft` | 작성중 | 반영하지 않음 — "작성중 N건"으로만 보고 |
| `complete` | 고객이 [완료하고 제출]을 누름 | **반영** — 최신본 하나만(`updated` → `revision` 순) |

- 모든 칸을 채운 것과 "이대로 진행해도 된다"는 다른 판단이다. 그래서 완료는 사람이 직접 표시한다
- 완료 뒤 내용을 고치면 **작성중으로 돌아간다**. 저장할 때마다 판(revision)이 오른다
- 이전 판 json 은 지우지 않아도 된다. 최신 완료본이 대신하고, 이전 판의 답은 두 번 세지 않는다

## 저장하는 두 경로
| 경로 | 어떻게 | 파일 이름 |
|---|---|---|
| ① 저장 서버(권장 — 같이 앉아서) | `python nova.py checklist` → 브라우저가 열림 → [임시저장] · [완료하고 제출] | 서버가 폴더를 읽어 `checklist_YYYYMMDD_NN` 을 매긴다. 같은 세션에서 다시 저장하면 같은 파일을 덮는다. json 과 md 가 함께 생긴다 |
| ② 파일 하나(멀리 있는 고객) | `docs/warehouse/outbound/checklist/checklist.html` 을 보낸다 → 고객이 [완료하고 제출]로 json 을 내려받아 돌려준다(중간에는 [임시저장]) → 이 폴더에 넣는다 | 브라우저는 폴더를 못 읽으므로 기본 `_01` 이다. 겹치면 넣을 때 번호를 바꾼다. md 는 `checklist.py md` 가 만든다 |

저장 서버는 `127.0.0.1` 에서만 받는다(이 PC 밖에서는 접속할 수 없다).

## 형식 — 왜 JSON 이고 JSONL 이 아닌가
- 고객 답 한 벌은 **그 시점의 상태(스냅샷)** 다. 그래서 JSON 이고, md 는 보기로 생성한다([ADR-004](../../../adr/ADR-004-ledger-formats.md) — 상태는 JSON, 보기는 생성 MD. MD 를 기계 입력으로 쓰지 않는다)
- 판의 이력은 파일 안 `revision` 과 git 이 가진다. 줄마다 쌓는 JSONL 이 필요한 "이벤트 이력"이 아니다

```json
{"form": "nova-checklist", "tree_version": "1", "status": "complete", "revision": 2,
 "created": "2026-11-04", "updated": "2026-11-04T15:20:00", "file": "checklist_20261104_01", "lv": 1,
 "answers": {"users.who": {"value": ["staff", "customer"], "other": "", "note": "", "state": "customer", "evidence": []}}}
```
- `state`
  - `customer`: 고객이 고름
  - `confirmed`: 자료에서 채운 것을 고객이 확인
  - `prefill`: 자료에서 채웠지만 확인 전 → 부족 항목
  - `unknown`: 건너뜀(스위치) → 부족 항목
- `skipped_sections`: 스위치로 건너뛴 섹션 ID 목록 → 그 섹션의 기본 질문이 부족 항목
- 보이는 질문의 답만 저장된다(부모 보기를 풀면 그 아래 답은 빠진다)

## 흐름
```
다른 입고 자료 ─/intake─▶ intake.json 발견 E-* ─/checklist fill─▶ checklist_prefill.json ─build─▶ checklist.html
      checklist.html(자료에서 채움) ─고객 클릭 · 확인 · 보충─▶ checklist_YYYYMMDD_NN.json (+ .md)
      ─checklist.py import─▶ intake.json(고객 답 = 발견 · 빈 것 = 부족 G-*) ─▶ /req-interview(부족한 것만) ─▶ /prd
```

## 검사
`python nova.py lint` 의 `checklist.py check` 가 다음을 검사한다.
- 트리 형식: ID · 보기 · PRD 영역 · 단계
- 자동 채움: 트리에 있는 값인지, 근거가 intake 에 실재하는지
- 받은 json: 형식 · 값
- 폼 · md 최신 여부(드리프트)

브라우저 동작은 `python nova.py checklist-smoke` 로 확인한다(단계 목록은 `scripts/checklist_smoke.py` 가 정본).
