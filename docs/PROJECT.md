# PROJECT — Nova 공통개발플랫폼

> 이 프로젝트가 **무엇이고 왜 있으며, 무엇이 되면 성공인가**를 적는 자리. 세션 시작 때 읽는다(`.claude/soul/MEMORY.md` 3단계). 참조: project-start-guide-05 `docs/state/PROJECT.md` 를 Nova 에 맞게 고쳤다([ADR-007](adr/ADR-007-soul-layer.md)).
> 계획 · 순서는 [master_plan](plans/master_plan.md), 요구는 [requirement](requirement/requirement_index.md) — 여기에는 **북극성과 판정**만 둔다(같은 사실을 두 곳에 쓰지 않는다).

## 북극성 — 두 축
1. **제품 축 — 무엇을 내보내는가**: 모든 새 프로그램이 **Nova 에서 생성되어**(`python nova.py new-project`) 첫날부터 같은 구조 · 같은 문서 프로세스 · 같은 공통 코드 · 같은 화면 규칙으로 시작한다. Nova 자신은 제품이 아니라 **제품을 만드는 골격**이다
2. **AI 축 — 복제본이 무엇을 물려받는가**: 새 프로젝트를 열면 규칙 · 게이트 · 디자인 정본과 함께, **누구와 일하는지 · 자기가 무엇인지 · 어떻게 답하는지**를 아는 AI 축(SOUL 레이어)이 함께 선다

⚠️ ①이 목적지이고 ②는 그 내용이다. 둘을 바꿔 읽으면(AI 축만 다듬으면) 내보내지 못한다.

## 문제
- **프로젝트마다 같은 것을 다시 만든다** — dayroom2 같은 실제 프로젝트에서 업무와 무관한 공통부(문서 프로세스 · 서비스 틀 · 인프라 생성 · 디자인 시스템 · 웹/모바일 골격)를 매번 새로 짰다
- **AI 가 세션마다 '일반 조수'로 다시 나타난다** — 말투 · 판단 원칙 · 언어 규칙이 흔들린다. 실제로 한국어 규칙을 여러 번 어겼다(규칙만 적어서는 뚫린다 → 훅으로 강제)
- **요구가 흩어진다** — 고객 자료 · 인터뷰 · 결정이 한곳에 이어지지 않으면 근거 없는 기능이 생긴다

## 주 사용자
- **사용자(한종열 · 기획 · 설계자)** — Nova 의 주인이자 첫 사용자(`.claude/soul/USER.md`)
- **Nova 위에서 일하는 AI** — 명령이 레일, 게이트가 안전망, SOUL 레이어가 정체성
- **Nova 로 새 프로젝트를 여는 사람** — 생성하면 첫날부터 초록, 남의 기록이 따라오지 않는다
- **고객** — 체크리스트 · 인터뷰로 요구를 말하고, 근거 있는 PRD 를 받는다

## 플랫폼이 값어치 있는가 — 판정 조건 (달성 선언이 아니다)
위 성공 기준은 "골격이 작동하는가"를, 이 절은 "플랫폼이 값어치 있는가"를 묻는다. 둘을 섞지 않는다. 핵심 칸은 **필요한 세계 수** — 이 저장소 하나로 잴 수 있는지, 새 프로젝트라는 둘째 세계가 있어야 하는지.

| 축 | 필요한 세계 | 지금 | 무엇을 재면 판정되나 |
|---|---|---|---|
| ① 개발 효율 | 2+ | ⏳ | Nova 로 만든 프로젝트와 아닌 프로젝트의 첫 기능까지 걸린 시간 |
| ② 통일성 — 저장소 안 | 1 | 🔎 | lint(토큰 · 생성물 · 대장 · 문서)가 규칙을 기계로 지킨다 |
| ② 통일성 — 프로젝트 사이 | 2+ | ⏳ | 두 생성 프로젝트가 같은 규칙 · 부품을 쓰는지 대조 |
| ③ 개발 기간 단축 | 2 | ⏳ | 첫 실제 프로젝트의 일정 기록 |
