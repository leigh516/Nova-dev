# STD-AX-001 — AI 자동화 등급 (AX) 표준

> **한 줄 요약:** UX 규칙([ux-heuristics](../conventions/ux-heuristics.md) H3 · H5)은 *"쓰기 동작을 어떻게 보여 주고 확인받는가"*(화면 층)를 정한다. 이 표준은 그 앞의 질문 — **"이 기능이 애초에 자동으로 실행돼도 되는가"**(정책 층)를 정한다. 두 층은 **L2 ↔ 확인 대화상자**에서 맞물린다.

- 상태: 표준(판정 의무) · 출처: project-start-guide-05 STD-AX-001 → Nova 코드 기준으로 다시 씀
- 적용 대상: AI 가 **조회 이상**을 하는 모든 기능. AI 기능이 없으면 면제(판정 기록)

## 자동화 등급 4단 — 기본값은 L1
| 등급 | 이름 | AI 가 하는 것 | 사람이 하는 것 | 화면 표현(Nova 컴포넌트) |
|---|---|---|---|---|
| **L0** | 관찰 · 요약 | 읽고 요약 · 분석 | 읽는다 | AI 표시 배지 + 출처 |
| **L1** | 초안 | 초안을 만든다(저장 안 함) | 검토 · 수정 · **사람이 저장** | 저장은 사람의 일반 `useAction` |
| **L2** | 승인 후 실행 | 실행안을 제시, 승인되면 실행 | **승인 / 취소** | `useConfirm` 확인 대화상자(파라미터를 숨기지 않는다 · 취소 항상 · 렌더만으로 실행 금지) |
| **L3** | 자율 실행 | **허용 목록** 작업을 스스로 | 사후 감사 | 이벤트 피드 + 감사 기록 |

- **기본값은 L1.** 올리려면 근거가 필요하고, 근거는 기능 단위로 세부 계획서 §0 에 남긴다
- **L3 는 허용 목록 작업만** — "위험하지 않은 것"이 아니라 "명시적으로 허용한 것"만(부정 목록은 항상 뚫린다)
- 등급이 애매하면 **낮춰 잡는다**

## 안전 규칙 (필수) — Nova 가 강제하는 것
### ① AI 는 별도 체계가 아니라 **또 하나의 사용자**
전용 서비스 계정 + **사람과 같은 권한 검사**(게이트웨이 RBAC, [권한 대장](../registry/permissions.md)). AI 전용 권한 체계를 따로 만들지 않는다.

### ② 감사는 분리한다 — `actor_type`
JWT 클레임 `actor_type: ai` → 게이트웨이 `x-actor-type` → `Principal.actor_type` · `nova_common.context.current_actor_type()` → 이벤트 봉투 `actor_type`(자동). "이건 누가 했나"에 언제나 답할 수 있다.

### ③ 승인함 불변식(L2)
- **승인자 ≠ 요청한 AI**(자기 승인 금지) — 승인 API 는 `principal(request).require_human("승인")`
- **TTL 자동 반려** — 방치된 승인 요청이 영원히 살지 않게
- **드라이런 우선** — 실행 전에 무엇이 바뀌는지(영향 건수) 먼저 보여 준다(UX H5)

### ④ 민감 데이터 노출 통제
개인정보 · 원가 등은 AI 에 넘기기 전 마스킹 · 필터. 화면의 마스킹은 *표시*를 막고, 이 조항은 *전달*을 막는다 — 둘 다 필요하다. [DB 사전](../registry/db-dictionary.md)의 `comment` 에 `PII` 를 표시해 대상을 찾는다.

### ⑤ 실패는 조용히 지나가지 않는다
자동 실행이 실패하면 **상태 변경 없음**을 밝히고 사람에게 알린다: "실행할 수 없습니다 — <사유> (상태 변경 없음)". `useAction` · `rememberAction` 의 오류 알림 문구 규칙(UX H9)을 따른다.

## AX-ready 3층 — 대장이 배당금이 된다
| 층 | 무엇 | Nova 에 이미 있는 것 |
|---|---|---|
| **지식층** | AI 가 읽을 지식 | [대장 4종](../registry/README.md) · `docs/` 정형 문서(요구 · 계획 · ADR) — grep · 청킹 친화 |
| **행위층** | 화면이 쓰는 그 API 를 AI 도 같은 권한으로 | 게이트웨이 `/v1` · 목록 계약 · 오류 봉투 |
| **트리거층** | 이벤트 구독 = 자동화 진입점 | [이벤트 대장](../registry/events.md) · 아웃박스 · 멱등 소비 |

## 계획서 §0 에서 확인할 것
- [ ] 이 기능의 AI 사용 시나리오(도구화 · 트리거)를 한 줄이라도 검토했는가
- [ ] 허용 등급(L0~L3)이 정해졌는가 — 정하지 않으면 L1
- [ ] L2 이상이면 승인 경로(`require_human`) · 감사(`actor_type`)가 설계에 있는가
